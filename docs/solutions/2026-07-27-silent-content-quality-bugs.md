# 三個「CI 全綠但產出爛掉」的內容品質 bug

日期：2026-07-27
Commit：`4543ca2`

## 問題

站上肉眼可見三類問題，但 CI 天天全綠、測試全過、沒有任何 error log：

1. 部分文章正文開頭是模型的推理過程，最嚴重一篇 20KB 全是英文 CoT，連 system prompt 的「撰寫規範」都外洩
2. 滿版簡繁誤譯：`975B 引數`、`長上下文擴充套件`、`JAX 主機解除安裝`、`區域性感知`、`最新程式庫檔案餵進 LLM`
3. 同一篇論文在相鄰兩天重複出現（CineMobile / DrugGen 2 / Flash-BoN / Jet-Long 整組在 07-10、07-11 各一次）

## Root Cause

三個獨立成因，但共享同一個 pattern：**都是「單側正確」造成的靜默失效**。

### ① 去重：兩側正規化不對稱

```python
# src/models.py — 比對時去版本後綴
canonical = re.sub(r"v\d+$", "", arxiv_id)

# src/utils.py — 存入時原樣（bug）
seen.add(f"arxiv:{arxiv_id}")
```

arxiv collector 存的 id 全帶 `v1`、hf_papers / semantic_scholar 都不帶。
歷史存 `arxiv:2607.03803v1`、今日算 `arxiv:2607.03803`，永遠比不到。
實測 07-11 的 79 篇帶 arxiv_id 項目中 **78 篇本該被擋卻全數漏網**。

同一個函式的 URL 那側早就修過一模一樣的問題，旁邊還留著註解解釋「兩側都要
經 `normalize_url`」——arxiv_id 這側漏了。

### ② 簡繁：profile 選錯 + 不冪等

兩個獨立根因疊在一起：

- **s2twp 的 TWPhrases 詞庫是為 Windows／一般軟體 UI 設計的**，套進 AI/ML
  語境單次轉換就錯：`参数→引數`、`扩展→擴充套件`、`卸载→解除安裝`、
  `局部→區域性`、`绑定→繫結`、`控件→控制元件`
- **s2twp 對已是繁體的輸入不冪等**：`文档` → `文件` → `檔案`。專案的雙層設計
  （來源端 Layer A + 生成端 Layer B）讓 Layer A 轉好的字進 prompt、LLM 複述、
  Layer B 再轉一次

第二點的傳播路徑不直觀：兩層並非直接串接，而是**透過 prompt 與 LLM 的複述**
間接串起來的。

### ③ 推理外洩：根因在 prompt

```
請先判斷內容類型（論文／開源專案／新聞），再依撰寫規範產出完整文章。
```

要求模型「先判斷」，模型就把判斷結果寫進正文了。`llm_chat` 早就支援
`validate=` 讓爛輸出降級，但生成端從來沒接上。

## 解法

| Bug | 修法 |
|---|---|
| ① | `get_seen_urls()` 套用與 `dedup_key()` 相同的 `re.sub(r"v\d+$", "", ...)` |
| ② | 新增 `_TERM_FIXES` 修正表；兩層改用不同 profile——Layer A 用 `s2twp`、Layer B 用新的 `to_traditional_shape_only()`（`s2tw`，無詞庫、對繁體冪等）；補 `tags` 的 Layer A validator |
| ③ | prompt 明確禁止輸出判斷過程；接上 `llm_chat(validate=)`；加 `strip_reasoning_preamble()` 剝除可救的前綴 |

## 可複用的 pattern

**1. 「產生 key」與「查詢 key」是兩條路徑，任何正規化都必須兩側同時做。**
這類 bug 不拋錯、不留 log，只會安靜地讓機制失效。查法：不要只讀產生端的
函式，把查詢端的集合實際 dump 出來跟當日算出的 key 逐一比對。
同一檔案裡「已經為別的欄位修過同類問題」的註解，是在提示還有其他欄位沒修。

**2. 冪等性要專門測「已經處理過的輸入」，不能只測原始輸入。**
簡繁轉換、正規化、清洗函式都適用。測 `f(简体) == 繁體` 會過，測
`f(f(简体)) == f(简体)` 才會抓到問題。

**3. 事後防線要先問「能不能救」，不要一律丟棄。**
21 篇推理外洩中有 17 篇只有開頭一句髒、正文完好。先 strip 再判斷，
省下 17 次沒必要的 LLM 重生成——在免費額度只有 50 次/天的專案裡這很關鍵。

**4. 修 LLM 輸出問題時，先看 prompt 有沒有在要求那個行為。**
「模型把分類寫進正文」的根因就是 prompt 叫它「先判斷內容類型」。
加防線之前先問這句話是不是自己寫的。

## 驗證方式

不靠測試自證，全部用真實資料：

- 去重：重放 2026-07-11 的真實 raw，統計本該被擋的比例（78/79）
- 簡繁：掃 7 月全部 raw 統計誤轉詞（183 處）；用真實中國來源標題走完整
  Layer A → Layer B 路徑確認穩定
- 推理外洩：對全部 2701 篇實際產出跑偵測，逐篇人工確認攔截原因（21 篇
  全部為真、零誤判）
- 端到端：實際呼叫 LLM 生成一篇（首選 model 404 自動降級到
  `tencent/hy3:free`），確認落盤文章以 📌 開頭、無外洩、無誤轉、無簡體

## 已知限制

- 修復**不回溯既有內容**：站上現存的 183 處誤轉詞、21 篇洩漏文章、重複文章
  都還在，需 `--force` 重跑才會消失
- 繁簡混雜的同一段文字（LLM 偶發吐半段簡體）仍會整段過 s2twp，該段內的
  繁體「文件」還是可能被轉成「檔案」。實務罕見，已寫進 docstring
