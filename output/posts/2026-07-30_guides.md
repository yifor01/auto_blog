📌 如何駕馭 Coding Agents？Simon Willison 分享提升 AI 編碼效能的實踐模式

TL;DR：透過掌握 Agentic Engineering 模式，讓 Claude Code 與 OpenAI Codex 成為更強大的開發助手。

隨著 AI 寫程式的成本大幅下降，開發者的角色正在發生轉變。如何從「親手撰寫每一行程式碼」轉向「引導 AI 代理人（Agent）進行開發」，已成為現代工程師必須面對的新課題。

🧩 **從寫程式轉向 Agentic Engineering**

在「寫程式已經變得很便宜」的時代，開發者的重心應放在如何利用 AI 產出更高品質的程式碼。這需要一種全新的思維模式，即「Agentic Engineering」，重點不在於替代思考，而是如何與代理人協作。

💡 **實踐高效開發的關鍵模式**

根據 Simon Willison 的經驗，與 Coding Agents（如 Claude Code 或 OpenAI Codex）協作時，應遵循以下核心原則：

*   **利用 Git 進行版本控制**：在與 Agent 協作時，將 Git 作為安全網，確保可以隨時回溯 Agent 產出的結果。
*   **採用 Red/Green TDD（測試驅動開發）**：這是一種極佳的協作流程。首先執行測試（Red），確認失敗，再交由 Agent 撰寫程式碼使測試通過（Green）。
*   **結合 Agentic Manual Testing**：除了自動化測試，手動測試在引導 Agent 進行複雜邏輯開發時依然不可或缺。
*   **利用 Subagents（子代理人）**：將大型任務拆解，讓 Agent 能夠調度更專注的子任務來處理。
*   **線性工作流與互動式解釋**：透過線性步驟引導 Agent，並要求其提供互動式的解釋，以建立對程式碼邏輯的深度理解。

⚠️ **應避免的開發反模式 (Anti-patterns)**

並非所有的 AI 輔助方式都有效。開發者需要識別並避免那些會降低開發品質的行為，例如過度依賴 AI 而放棄了對核心邏輯的掌握，或是在沒有測試保障的情況下盲目接受 AI 的產出。

🎯 **實務啟示**

面對 AI 驅動的開發環境，工程師的價值正從「實作細節」轉向「架構設計」與「驗證邏輯」。建議從 TDD 與 Git 協作開始，將 Agent 視為一個可以被精確指令引導的「初級工程師」，透過嚴謹的測試流程來確保產出品質。
