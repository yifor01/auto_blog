📌 vLLM v0.28.0：270 位貢獻者的推理引擎大更新

TL;DR：新版針對 Kimi-K3、DeepSeek V4 全面優化核心與投機解碼，並把 KV cache 分層卸載做到磁碟層。

一次發布涵蓋 584 個 commit、270 位貢獻者，其中 76 位是首次貢獻——這個規模本身就說明了 vLLM 在開源推理基礎設施生態裡的位置。

🤔 這次更新在解決什麼問題

vLLM 是目前主流的開源 LLM 推理服務框架之一，v0.28.0 的重點集中在讓新一代大型 MoE 模型（Kimi-K3、DeepSeek V4）跑得更快、更省記憶體，同時擴充投機解碼、Model Runner V2 執行引擎，以及 KV cache 分層卸載等基礎能力。

🧩 Kimi-K3、DeepSeek V4 是這次的重頭戲

Kimi-K3 效能推進：新增 Decode Context Parallel（DCP）支援、融合的 FlashKDA decode／prefill 核心、MegaMoE 的 SiTU activation 支援、用於序列平行的 GEMM-RS、合併 all-gather 操作帶來 1.5 到 3 倍的核心層級加速、自適應投機 token 預算讓 DSpark 的首字延遲（TTFT）提升約 60%，以及選用性的共享專家切分，每張 GPU 可省下約 17 GiB 記憶體。Kimi-K3 現在也能透過 V2 model runner 在 ROCm 上執行。

DeepSeek V4：稀疏 MLA 在一般解碼、MTP、DSpark 投機解碼路徑上全面打通，並加入 AMD Quark NVFP4 支援、reasoning-effort 提示與映射、稀疏 top-k metadata 核心優化、收窄的 eager CUDA graph 區域，以及在 gfx11、gfx950 上的 ROCm 支援。

投機解碼進一步擴充：新增 DFlash2（搭配 local convolution 與候選選擇器）、DSpark 信心分數排程驗證，草稿模型的非同步排程現在預設啟用。

Model Runner V2 持續成熟，加入 E/P/D 分離架構、權重卸載、多層 MTP KV cache、encoder CUDA graph、decoder token-wise pooling 與 Transformers pooling 模型支援、無 attention 模型，以及 thinking_token_budget 設定。KV cache 分層卸載新增磁碟卸載支援、可透過 module_path 掛載外部次層管理器、部分次層載入結果、卸載指標，以及與平行策略無關的統一 CPU layout。Rust 前端與 gRPC 部分則新增獨立 renderer、透過 gRPC 的多模態圖片推論、明確的 data-parallel rank 路由、RL 生命週期控制，protobuf schema 也已發佈到 Buf。新的預設值也值得注意：max_num_batched_tokens 從 8192 提高到 16384，Mamba 模型預設開啟 prefix caching，Blackwell 架構的 CUDA graph capture 預設值提高到 1024。

⚠️ 升級前要注意的 breaking changes

bitsandbytes 支援搬到外部（out-of-tree）外掛；Transformers 版本升級到 5.15.0；已棄用的 calculate_kv_scales 執行期 KV scale 計算被移除；override_attention_dtype 參數也被移除。升級前建議先確認自己的部署有沒有依賴這幾項。

📊 新模型與安裝方式

本版也新增模型支援，包括 Muse Glimmer、Ling 3.0 Flash（BF16、MTP、parser 支援，加上 FP8 變體與混合 MXFP4 routed experts）、Dots3 的原生多模態支援，以及 Interns2mobius。安裝方式維持一致：pip install vllm（CUDA 13.0），或用 uv pip install vllm --torch-backend=auto；ROCm、CPU、XPU 皆提供對應的 Docker 映像檔與預編譯 wheel。這次發布在 Hacker News 上獲得 106 點、36 則留言的討論。

🎯 對自架推理服務的團隊意義

這版最直接的收益是 Kimi-K3、DeepSeek V4 這類大型 MoE 模型的吞吐與記憶體效率提升，以及磁碟層 KV cache 卸載讓長上下文服務的成本曲線更平緩；升級前務必檢查 bitsandbytes、Transformers 版本與已移除參數這幾項 breaking changes，避免部署中斷。
