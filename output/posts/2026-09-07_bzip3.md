📌 BZip3:用 context mixing 讓文字壓縮再進化的開源工具

TL;DR：BZip3 是 BZip2 的精神後繼者,靠 context mixing 熵編碼與 suffix array 版 BWT,在文字與程式碼壓縮上實測大幅超越前代。

同樣是壓縮一份 Perl5 全歷史版本的原始碼合集,BZip2 壓出 34 億位元組,而 BZip3 在更高設定下只需要 5.46 億位元組,體積不到三分之一。這是開源專案 BZip3 在自己的 benchmark 中攤出的數字。

🤔 **解決什麼問題**

BZip3 定位為「更好、更快、更強」的 BZip2 精神後繼者,README 明確指出它特別擅長壓縮文字或程式碼,鎖定的是需要高壓縮比、且原始資料具有大量重複結構(如原始碼、文字語料庫)的使用情境。

🧩 **架構:三段式管線的組合拳**

根據專案說明,BZip3 的技術核心由三個部分組成:

- **Order-0 context mixing 熵編碼器**:負責最終的熵編碼壓縮階段。
- **基於 suffix array 的快速 Burrows-Wheeler transform(BWT)**:BWT 部分沿用並改良自 Ilya Grebnov 的 libsais 函式庫。
- **RLE + LZP + LZ77 風格字串比對,搭配 PPM 風格的 context modeling**:在進入熵編碼前先做一輪基於 Lempel-Ziv 與預測式編碼(Prediction)的前處理,壓縮重複與可預測的內容。

專案作者也提到,其中的 BWT 後處理編碼器(BWT post-coder)是參考 Ilya Muravyov 的公共領域實作改寫而成。

📊 **實測數據:壓縮率與解壓縮速度並重**

作者用「歷來所有 Perl5 版本」打包成的 tar 檔做基準測試,結果整理如下:

| 壓縮方法 | 壓縮後大小(bytes) |
|---|---|
| LZMA (xz) | 2,056,645,240 |
| Zstandard | 3,076,143,660 |
| bzip2 -9 | 3,441,163,911 |
| bzip3 -b 256 | 1,001,957,587 |
| bzip3 -b 511 | 546,456,978 |

解壓縮時間方面(使用 WD Blue 傳統硬碟測試):LZMA(xz)約 4 分 40 秒,bzip3(平行模式)約 4 分 06 秒,Zstandard 約 3 分 51 秒,bzip2 則需 9 分 22 秒。作者也提到,搭配 lrzip 做長距離去重後再用 bzip3 壓縮尾段資料,效果又優於搭配 LZMA 或 bzip2 的組合。此外,README 指出在 x64 Linux 搭配 clang13 編譯下,單執行緒最高可達約 17 MiB/s 壓縮、23 MiB/s 解壓縮速度,並提醒 Windows 與 32 位元版本可能明顯較慢。

🧩 **安裝方式**

README 提供的標準流程為:從 git clone 取得原始碼後執行 `./bootstrap.sh`,接著依序執行 `./configure`、`make`、`sudo make install`;macOS 使用者也可以透過 Homebrew 執行 `brew install bzip3` 安裝。

⚠️ **作者自己強調的風險與限制**

專案 README 罕見地用大寫字母鄭重聲明:使用本程式壓縮任何資料前,必須接受「資料有可能無法還原」的風險,理由是壓縮演算法的複雜度與各種極低機率的特殊情況,使得無法完全排除潛在 bug 的存在。作者強調這並非暗示程式本身不可靠,而是提醒使用者對任何壓縮工具都應保有此警覺。授權方面,BZip3 整體採 LGPLv3 單一授權(而非 LGPLv3 與 Apache 2.0 雙授權),但其中使用的 libsais 與 LZP 程式碼、部分 build 工具則各自維持原本的 Apache 2.0、GPL-3+ 等授權條款。

🎯 **實務啟示**

如果你的應用場景是壓縮原始碼庫、文字語料或其他高度重複的文字型資料,BZip3 提供了在壓縮比與速度之間的另一個實測選項,值得與現有的 xz、zstd 方案做並排比較;但基於作者自己強調的資料完整性警語,在正式導入前建議先在非關鍵資料上做完整的壓縮還原驗證。
