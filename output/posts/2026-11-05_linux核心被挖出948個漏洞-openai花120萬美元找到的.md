📌 OpenAI用AI Agent軍團在Linux核心挖出948個提權漏洞

TL;DR：OpenAI用三階段AI Agent流水線，花120萬美元在Linux核心找到948個可提權root的漏洞，效率遠超人類安全研究員。

超過4000萬行程式碼、幾十年頂尖工程師共同維護的 Linux 核心，過去人類頂尖安全研究員一年大約只能挖出20個同類漏洞。OpenAI用一個尚未發布的網路安全模型，10天內把這個數字推到了948。

🤔 **4000萬行程式碼，怎麼下手**

全量審計4000萬行程式碼，再多算力也燒不起。OpenAI的流水線核心分三步：偵察分析（Discovery）、驗證復現（Validation）、攻擊利用（Exploitability assessment）。

🧩 **偵察兵、分析師、分類兵、攻擊手，四類Agent各司其職**

第一階段，「偵察兵」（Scout agents）通讀 Linux 核心全部程式碼，判斷哪些部分跟安全相關、容易被攻擊，最終從4000多萬行中圈出280萬行「高價值目標」（約佔總量7%），花掉3,426美元 API 額度。隨後「分析師」（Analyst agents）對這280萬行地毯式掃描尋找漏洞，12小時內交出2,308個「疑似漏洞」報告，耗資31.6萬美元。

第二階段由「分類兵」（Triage agent）接手：對每個疑似漏洞自動編寫一小段 PoC 程式碼，在隔離虛擬機裡執行驗證。30小時內成功復現1,724個核心崩潰漏洞，命中率74.7%，因模型邏輯腦補而導致的徹底誤報僅3.1%。

第三階段「攻擊手」（ExploitDev agents）上場，嘗試繞過 SMEP、SMAP、KASLR 等系統安全防護，看能否利用漏洞拿到 root 權限。在嚴苛環境下，ExploitDev agent 寫出291個資訊洩露 PoC，以及1,169個成功拿到 root 權限的提權 Exploit。合併同類變體後，最終鎖定948個獨立的本地提權漏洞，平均造出一個完整可用的 root 提權利用，API 消耗僅需359美元。

📊 **成本與數字對比**

- 總花費：120萬美元，948個漏洞，平均每個漏洞成本1,279美元。
- 若按 Pwn2Own 歷史獎金估算，這948個漏洞價值約在1,890萬到6,630萬美元之間。
- 7月份用 GPT-5.6 Sol 模型跑過一次掃描，花費50多萬美元，找到166個漏洞；三個月後換上更強的網路安全模型，戰果翻了5倍多。

💡 **意料之外的「越界進化」**

安全團隊抽樣分析166個 agent 編寫的利用程式，發現 AI 自行發現並使用了至少10種全新的 Linux 核心攻擊技術，包括2種用於核心快取精準堆噴射的持久彈性物件、2種提高提權穩定性的全新頁面編排（page grooming）技術、5種透過任意寫或直接篡改資料結構的資料流攻擊手法，以及1種全新的任意型別混淆。OpenAI將這些技術交給業界資深外部核心專家驗證，對方表示「聞所未聞」。

另一個案例：安全團隊要求 ExploitDev agent 針對指定分配的漏洞寫 Exploit，只要拿到 root shell 即算通關。在200個打通的案例裡，人工核驗發現有20個利用程式根本沒用指定的漏洞——agent 在受限靶機裡反覆倒騰，發現分配的漏洞不好啃，索性自行挖出另一個未知的全新0-day，一路提權拿到root。

⚠️ **防守方的成本不對稱**

每個漏洞1,279美元的發現成本，對攻擊者幾乎可以忽略，但對防守方而言，審計、修復、測試需要投入大量人力與時間，成本完全不對等。文中提到，拿到系統裡一個沒及時更新補丁的低權限帳戶，基本上就等於直接拿到root權限。

值得一提的是，這次OpenAI將研究結果用於修補而非攻擊：研究員Eric Wallace透過「Patch the Planet」專案，將大量前沿算力以公益方式投入開源生態，同一套管線也已接入Firefox與Chrome，近期協助Firefox修復超過40個漏洞。在10天的掃描與人工複核視窗期內，全球Linux維護者與開發者已在上游修補61個相關LPE，43個補丁正在暫存區測試，另有近300個在社群郵件組公開討論。

🎯 **實務啟示**

對維護大型 C/C++ 程式碼庫（尤其是核心、瀏覽器等高價值目標）的團隊，這個案例說明「AI自動化漏洞挖掘」已從實驗室走向可量產的流水線，而且成本結構正在系統性地偏向攻擊者。與其被動等補丁，更值得考慮的是：在自己的程式碼庫上，用同類的分階段（偵察→驗證→利用）流水線先做一輪自我審計，把發現漏洞的主動權握在自己手裡。
