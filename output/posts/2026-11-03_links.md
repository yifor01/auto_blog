📌 拆解 ChatGPT 帳號劫持漏洞：從虛擬鍵盤到 YouTube 執行 JS

TL;DR：Parameter Labs 找出一條跨越 postMessage、innerHTML 與 CSP 白名單的攻擊鏈，能透過一個分享連結竊取 ChatGPT 用戶私密資料。

一個看起來無害的 ChatGPT 分享連結，只要已登入的使用者點開，私密資料就可能被悄悄打包外洩。而這條攻擊鏈的起點，居然只是一個用來輸入數學公式的虛擬鍵盤元件。

🤔 沙箱 iframe 本該是安全邊界

ChatGPT 的 HTML previews（前身是 Canvas）功能，讓互動式的自訂 HTML 應用顯示在沙箱化的 iframe 中。這個隔離機制之所以重要，是因為它要防止不受信任的程式碼接觸到 OpenAI 的 API 與使用者私密資料。Parameter Labs 發現的這條攻擊鏈，正是一步步突破了這層隔離。

🧩 攻擊鏈拆解：五個環節串成一條逃逸路徑

1. OpenAI 在圖表功能中使用了 MathLive 這個 JavaScript 函式庫，而它內建一個虛擬鍵盤，可以透過沙箱化 iframe 呼叫 `postMessage()`，在父頁面中被觸發。
2. 父頁面接收這類訊息的程式碼使用了 `innerHTML` 來插入內容，而且沒有任何機制限制「哪些 iframe 可以呼叫這個方法」，導致包括 HTML preview frame 在內的其他沙箱化 iframe，都能對父頁面插入自訂 HTML。
3. 雖然 `innerHTML` 不會直接執行 `<script>` 標籤，但攻擊者可以利用它插入一個「不受 sandbox 限制」的新 iframe。
4. OpenAI 的 CSP（Content Security Policy）規則完全封鎖了 inline script，也只允許從少數網域載入 script——但其中一個被允許的網域正是 YouTube，而 YouTube 的 oEmbed 端點可以被利用來反射回 JavaScript，進而被執行。
5. 一旦在 ChatGPT 頁面上取得 JavaScript 執行權，攻擊者就能輕易呼叫私密 API 取得使用者資料，再透過圖片參照（image reference）把資料外洩出去。

📊 最終結果與處置

最終結果是：攻擊者可以製作一個 ChatGPT 分享連結，只要另一位已登入的使用者造訪，就能竊取其私密資料，或代表其執行動作。OpenAI 已經修補此漏洞，並支付了 5,000 美元的 bug bounty；Simon Willison 認為，對於這麼嚴重的一個漏洞，這個賞金金額「有點便宜」。

💡 CSP 白名單的脆弱一環

這個案例的關鍵在於，即便正確封鎖了 inline script、也把可載入 script 的網域限制到「少數」，只要白名單中有任何一個網域存在可被濫用的反射端點（如此處的 YouTube oEmbed），整套沙箱防禦就可能被繞過。同時，`postMessage()` 搭配 `innerHTML` 在多 iframe 架構下，如果沒有限制訊息來源，等同於對同頁面所有 iframe 開放同等權限，無論它們是否應該被信任。

🎯 實務啟示

對於設計類似多租戶、沙箱化 UI 架構（Canvas、Artifacts、外掛系統等）的工程師，這是值得照搬去檢查自家系統的三個重點：postMessage 的接收端是否無差別信任所有來源 iframe；`innerHTML` 等危險 API 是否暴露在跨 frame 通訊路徑上；以及 CSP 白名單中的每一個第三方網域，是否存在可能被濫用的反射型端點（如 oEmbed、JSONP）。
