📌 Anthropic 不再考程式面試題,改看「誰夠餓」

TL;DR：Anthropic 招聘主管宣布廢除傳統程式面試,理由是 Claude 已經比多數應試者更會寫 code。

當 Claude 寫 React 元件、甚至組合語言都比大多數應聘者熟練時,再出一道「寫個 Fizzbuzz」的面試題,到底在測什麼?

🤔 **「考程式」已經失去鑑別力**

根據 Latent Space 的 AINews 彙整,身兼 Anthropic 招聘主管的 Felix Rieseberg 這個月正式停止在面試中要求候選人做傳統 coding interview。他的理由很直接:考 React 小題目,就像考應聘者懂不懂組合語言一樣沒有意義,因為 Claude 現在兩者都做得更好。他觀察到,團隊裡最有貢獻的工程師,成績往往不取決於這類測驗的表現。

🧩 **他提出的新評估標準**

Rieseberg 引用 Patrick McKenzie 2011 年的一句話:「工程師被僱用是為了創造商業價值,不是為了寫程式」,並延伸出幾個判斷重點:

- **拿商業影響力換掉待辦清單**:評估一個人是否在解決真正重要的問題,而不是看他清掉了多少 ticket。
- **挑一個夠大膽的點子**:鼓勵提出幾個如果成功會「大幅」改善組織目標的想法,而不是保守求穩。
- **一個週末做出來**:他觀察到,小團隊或單人工程師常常跳過寫 PRD、找共識、排設計師時程的流程,直接做出一個能跑的原型。
- **只做一個好點子**:他指出junior工程師常見的錯誤,是把太多想法塞進同一個原型,結果三個好點子被二十個壞點子淹沒。
- **善用自己的新鮮視角**:如果做的是 user-facing 的產品,新人對使用者的同理心反而是優勢,能更快看出產品哪裡卡。

🎯 **對工程師的實務啟示**

如果連面試官都不再把「會不會寫程式」當作門檻,那麼求職者與在職工程師真正該展示的,是能否識別值得做的問題、能否快速把想法變成可驗證的原型,而不是刷題能力。這也呼應了同一篇彙整裡提到的其他趨勢:Google Genie 4、Artificial Analysis Index v5 等評測與模型本身都在快速迭代,但「誰能把 AI 工具轉化成商業成果」才是現在被看重的能力。
