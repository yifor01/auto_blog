📌 【Simon Willison 指南】如何與 Claude Code 與 OpenAI Codex 協作，發揮編碼代理的最大效能？

TL;DR：透過掌握 Agentic Engineering 模式，讓 AI 代理從單純寫程式轉向協助開發高品質程式碼。

當「寫程式變得很便宜」成為現實，工程師的角色正在發生轉變。面對 Claude Code 或 OpenAI Codex 這類編碼代理（Coding Agents），重點不再只是如何生成程式碼，而是如何透過正確的開發模式，確保 AI 產出的品質與可靠性。

🧩 **從編碼轉向「代理式工程」（Agentic Engineering）**

隨著 AI 能力提升，我們正進入一個新的開發範式。Simon Willison 在其指南中探討了「什麼是代理式工程」，並指出開發者應該利用 AI 來協助產出更好的程式碼，而非僅僅是為了追求速度。

💡 **提升效能的實踐模式與最佳實踐**

指南中整理了多個維度的實踐方法，幫助工程師從單純的「指令下達者」轉型為「系統設計者」：

- **TDD 與測試驅動**：強調「先跑測試」的重要性。透過紅/綠測試（Red/Green TDD）迴圈，利用測試確保代理產出的結果符合預期。
- **Git 的整合使用**：如何有效地將 Git 版本控制與編碼代理結合，以管理 AI 產出的變更。
- **子代理（Subagents）的概念**：理解代理如何拆解任務並透過子代理來執行複雜工作。
- **互動式說明與線性導覽**：利用 AI 進行互動式的程式碼解釋，並透過線性導覽（Linear walkthroughs）來掌握開發流程。
- **手動測試與驗證**：除了自動化測試，代理式手動測試（Agentic manual testing）也是確保系統穩定的關鍵。

⚠️ **避開反模式（Anti-patterns）**

在與代理協作時，並非所有的行為都能帶來正面影響。指南特別提醒開發者要識別並避免「反模式」（Anti-patterns），即那些會降低開發品質或造成混亂的錯誤使用方式。

🎯 **實務啟示**

面對編碼代理，工程師的核心價值在於「掌握複雜度」與「驗證正確性」。建議開發者應將重心從「如何寫出程式碼」轉移到「如何設計測試流程」以及「如何有效管理 AI 產出的變更」，並學會將瑣碎的重複工作（如 GIF 最佳化、新增內容格式）委派給代理處理，自己則專注於系統架構與核心邏輯。
