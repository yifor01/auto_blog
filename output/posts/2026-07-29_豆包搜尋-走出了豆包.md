📌 【火山引擎】豆包搜尋開放 API：不再只給網址，直接讓 Agent 拿走「能用的資訊」

TL;DR：豆包搜尋將搜尋能力拆解為 API、MCP 與 Skill，提供包含摘要與 Markdown 節選的結構化資料，協助 Agent 跳過讀取網頁的冗餘步驟。

當大模型（LLM）面對新事件、新版本或即時價格時，受限於訓練知識的截止日期（Knowledge Cutoff），單靠模型內部的「存量知識」往往無法應對。傳統搜尋僅提供網頁連結，Agent 仍需自行開啟頁面、理解正文並抽取資訊。

豆包搜尋的目標，是省下這段反覆讀取與處理網頁的過程，讓搜尋結果能直接進入 Agent 的下一步任務。

🧩 **不只是搜尋網頁，而是提供「可直接使用的資訊」**

與傳統搜尋僅返回網頁入口不同，豆包搜尋在返回結果時，會同時帶回關鍵欄位，讓 Agent 能直接進行判斷與處理：

- **信源名稱與權威分級**：判斷資料可靠度。
- **釋出時間**：判斷資訊是否足夠新。
- **正文摘要**：快速掌握內容重點。
- **原文 Markdown 節選**：直接提供可供引用的結構化內容。

以「菲爾茲獎」為例，Agent 可以利用這些欄位，從政府官網、媒體報導與專業機構的資料中，精準提取獲獎名單、研究貢獻與專家評價，而不需要再進行二次解析。

🛠️ **開發者如何接入？**

火山引擎將豆包 APP 背後的搜尋能力單獨拆解，透過 API、MCP、Skill 等方式開放給企業與開發者。

在實測環境中（以 Mac 本地搭建 OpenClaw 並接入 Doubao-Seed-Evolving 為例），開發者可以透過單一指令安裝 `byted-web-search` Skill：

`npx skills add https://skills.volces.com/skills/bytedance/agentkit-samples -s byted-web-search —agent openclaw`

配置完成後，即可在 Agent 的 Prompt 中指定呼叫該搜尋功能。

📊 **實測案例：對即時資訊的反應速度**

在針對「Kimi K3 開源」這一極新事件的測試中，豆包搜尋展現了對最新資訊的定位能力：

- **資料時效性**：回傳結果包含 7 月 27 日至 28 日的最新報導。
- **資訊完整度**：
    - 包含模型權重、技術報告及訓練基礎設施（如 MoonEP、FlashKDA 等）。
    - 包含模型參數、GitHub/Hugging Face 入口、部署要求與 API 價格。
    - 包含授權範圍說明（例如：公開權重不等於同步開源完整訓練程式碼）。

💰 **服務模式**

目前豆包搜尋已正式面向企業與開發者開放，提供以下方案：
- **免費額度**：每月贈送 500 次免費搜尋額度。
- **付費方式**：支援按量後付費或訂閱月卡。

🎯 **實務啟示**

對於開發 AI Agent 的工程師來說，搜尋能力的關鍵已從「能不能找到網頁」轉向「返回的資訊能否直接進入下一步任務」。結構化、具備權威分級與摘要的搜尋結果，能大幅降低 Agent 在處理 RAG（檢索增強生成）時的運算成本與錯誤率。
