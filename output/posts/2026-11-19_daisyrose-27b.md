📌 RadixArk 發布 DaisyRose-27B：長程 Agent 任務 pass@1 從 5.6% 衝到 12.0%

TL;DR：RadixArk 用自家 RL 框架 Miles，以 144 張 H200、18 天訓練出開源長程 agent 模型 DaisyRose-27B。

長程 agent 任務（session 動輒上百萬 token、上百次工具呼叫）一直是 LLM 的硬骨頭。RadixArk 這次用僅 1,200 筆精心設計的訓練任務,就把 Terminal-Bench 4.1 的 pass@1 從 5.6% 推到 12.0%，背後靠的是資料設計與訓練基礎設施的雙重優化。

🤔 **核心問題：如何用有限算力訓練出會做長任務的 agent**

DaisyRose-27B 以 Qwen3.8-27B 為基礎，用強化學習在長程 agent 任務上做後訓練，訓練規模是 144 張 H200 GPU、18 天、僅 1,200 筆精選任務。RadixArk 表示 DaisyRose-27B 在每一項列出的 benchmark 上都優於原始 Qwen3.8-27B，其中增幅最大的就是 Terminal-Bench 4.1。

🧩 **方法：精選任務 + 異步訓練 + 自建 sandbox**

**訓練資料**：RadixArk 與 Eigent AI 合作，從 Eigent AI 涵蓋機器學習、軟體工程、科學等領域的大型任務池出發，共同打造出數千個候選任務，最終篩選出約 1,200 筆進入訓練集。篩選依據三個原則：

1. 每個任務要針對性觸發原始模型會犯的特定錯誤——團隊先在每個候選任務上跑一次原始 Qwen3.8-27B，再重新設計任務讓它暴露出該停止犯的錯誤。
2. 每個任務的 solve rate 要調整到「不會太簡單也不會太難」的區間,才利於模型學習。
3. 每個任務是一條串接多個問題的長任務鏈，agent 必須走過多階段的推理、規劃與執行；單次嘗試最多給 1.5 小時的 sandbox 時間，超過 100 次工具呼叫、超過 256k 輸出 token。團隊逐一審查每個任務與模型的嘗試記錄，任何能靠「作弊」通過或有設計缺陷的任務都會修正或剔除，確保沒有 reward hacking 的空間。

**訓練基礎設施**：用 RadixArk 自家開源 RL 框架 Miles，以全異步模式運作——agent 持續工作、模型持續學習，兩者互不等待。128 張 H200 跑 agent 推論，另外 16 張跑 trainer 學習軌跡，每一步訓練完，更新後的模型就推送給負責跑 agent 的 128 張 GPU。每一步訓練會從少數極長的 session（最長達 100 萬 token）學習，透過 harness 摘要折疊成多條軌跡。

**Sandbox 服務**：所有訓練過程中的 agent 嘗試都跑在自家建置於開源 AgentENV 專案之上的 sandbox 服務（RadixArk 亦回饋修補給該專案）。

📊 **數字：訓練成本降 57%，端到端快 2 倍**

- 本次發布的訓練運行中，每張 GPU 有 37% 的峰值運算量投入有效訓練工作（MFU），而基於 Megatron 的開源 trainer 在可比較的運行中只有 16%，換算同等訓練所需 GPU 時間少了 57%。
- 這個差距在 MoE 模型上更大：Qwen3.6-35B-A3B 上快 6.2 倍，約 300B 參數的 GLM-5.3-Flash 上超過 10 倍。
- 算入 agent 執行任務的時間，本次發布運行在 144 張 GPU 上達到每秒約 16,800 token，開源 trainer 在相同硬體上約 8,300 token，等於端到端快 2 倍。
- 本次運行在 144 張 H200 上跑了數週，累積 63,000 GPU 小時，從頭到尾速度與效率維持穩定。
- 從 9 月中到 11 月中，sandbox 服務共跑了約 944,000 個 sandbox，同時最多並行 1,566 個；服務規模從單臺機器成長到最多 12 臺，期間上線了十次升級（幾乎都在訓練運行中完成），整體九週內 sandbox 建立成功率達 99%，10 月下旬後提升到 99.95% 以上。
- 相較於常見的雲端 sandbox 服務商，RadixArk 自建的 sandbox 雲端基礎設施成本低了約 80%，主要靠讓每個 sandbox 的記憶體用量隨實際需求動態伸縮。

💡 **開源釋出，可直接下載或自行訓練**

DaisyRose-27B 提供 BF16、FP8、NVFP4 三種 checkpoint，可在 Hugging Face 下載；RL 訓練框架 Miles 同樣開源，供其他團隊訓練自己的 agent 模型。

🎯 **實務啟示**

如果你在用開源 RL 訓練框架訓練 agent 模型卻苦於 GPU 利用率低，這份報告指出的瓶頸值得對照檢查：MFU、異步 inference/trainer 分離比例、以及 sandbox 的資源彈性配置，都是能直接影響訓練成本與速度的槓桿點。此外,任務設計上「針對模型已知錯誤重新設計任務、調整 solve rate 區間、排除可被作弊通過的任務」這套篩選邏輯，對自建 RL 訓練資料集也有參考價值。
