📌 Loop Transformer 悄悄回潮：GLM-5.4 與本週幾則 AI 筆記

TL;DR：GLM-5.4 用「迴圈式」架構加深網路而不增加參數量，是本週最值得工程師留意的技術訊號。

同一週內，兩個不同團隊各自提到「looped transformer」這個詞，這種巧合通常意味著某個技術方向正在悄悄形成共識。

🧩 **GLM-5.4 的 Loop Transformer，加深網路但不加參數**

中國 AI 實驗室 Z.ai 發布的 GLM-5.4，是該系列第一個採用 looped transformer（迴圈式 transformer）架構的模型。官方說法是：標準 transformer 的每一層在一次前向傳播中只跑一次；而在 loop transformer 裡，一組共享權重的層會迭代跑多次，逐步精煉前一輪產生的隱藏狀態（hidden state），藉此在不增加參數量的前提下讓網路變得更深。

這不是本週唯一一次看到這個概念。Thinking Machines Lab 在 11 月 20 日發布的 Inkling 2 Mini，同樣被描述為 loop transformer——每個 token 都會讓模型的中間層跑三次，讓模型能用更少 token 做更多推理，作者特別點出這對 agentic coding 這類依賴推理品質的任務有幫助。

📊 **其他值得一提的觀察**

- GLM-5.4 目前還沒開源權重，官方表示會在完成「必要的安全強化」後負責任地開源。作者 Simon Willison 透過 Z.ai 的 Coding Plan 訂閱才拿到 API 存取權，發現該訂閱與一般 API 共用同一套 OpenAI 相容的 Responses API endpoint。
- 他做了 GLM 5.1 到 5.4 四代「pelican riding a bicycle」測試圖的對照，觀察到 5.3 與 5.4 的畫風明顯更接近 OpenAI、Anthropic 等主流模型的風格，不再像 5.1、5.2 那樣有自己獨特的畫風。
- 另外幾則連結也值得一提：歷史學者 Mark Humphries 用 GPT-6.2 Astra，僅給予最少提示，就在 22 分鐘內自主找出耶魯 Beinecke 圖書館一本 1808 年匿名素描本的作者，過程中模型從一份罕見的紙本檔案找到線索並提出可驗證的假設；Graham Dumpleton（mod_wsgi 作者）正在用 AI 輔助打造新的 Rust 伺服器 Muru，專門服務 Python 的 ASGI/WSGI 應用程式，並詳細記錄了開發過程；SQLite 的 sqlite3_rsync 工具則可以透過 SSH 把資料庫快照同步到另一臺機器，不需要先在本機建立完整副本，對磁碟空間緊張的小型機器相當實用，雖然這則與生成式 AI 本身關聯較低。

💡 **為什麼 loop transformer 值得關注**

兩個獨立團隊在同一週各自推出以「迴圈迭代層」取代「增加參數量」的設計，且都特別強調對 agentic / coding 類任務的推理品質有幫助，這暗示業界正在尋找「不靠堆參數也能堆深度」的新槓桿。

⚠️ **目前仍是半開放狀態**

GLM-5.4 尚未開源權重，且 5.4 暫時無法透過一般 API 存取，只能透過 Coding Plan 訂閱使用，這對想自行測試或微調的工程師來說仍是一道門檻。

🎯 **實務啟示**

如果你的工作涉及 agentic coding 或需要模型做多步推理，loop transformer 是值得追蹤的架構方向；同時也可以留意 GLM 的開源權重釋出時程，一旦開放將是對比「迴圈深度 vs. 參數規模」效益的好機會。
