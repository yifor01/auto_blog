📌 OpenAI 官方案例：Clay 如何用 GPT-6 模型群重塑銷售工作流

TL;DR：Clay 整合 Codex 與 ChatGPT，用 GPT-6 系列模型讓業務團隊秒懂客戶脈絡。

業務團隊手上往往握有大量客戶資料，卻常常抓不到那個能打動客戶的切入點。這正是 Clay 想解決的問題。

🤔 業務的痛點：資料多，洞察少

Clay 自我定位為「self-learning revenue engine」，協助使用者建立公司與聯絡人名單，透過 agent 進行資料 enrichment，再把這些資訊轉化為 go-to-market 的行動方案。Clay 的 AI 負責人 Jeff Barg 指出，即使業務手上資料充足，仍很難判斷「什麼才是真正重要的」，也難以據此發展出有效的提案策略。

🧩 把 Clay 帶進 Codex 與 ChatGPT

Clay 把能力延伸到使用者原本就在用的工具裡：

- Codex 整合：讓開發者在 Codex 中建立並執行 go-to-market 流程，業務則能用這些流程研究客戶名單或正在推進的交易。Jeff 觀察到，表現最好的業務正是最懂得運用 Codex 整合自家系統資料與公開資料集的人。
- ChatGPT plugin：把同一套客戶資料帶進 ChatGPT，讓業務不用離開對話視窗就能深入了解潛在客戶。Jeff 形容這個 plugin「取得了很大的成功」。

💡 模型分級：用 Responses API 兼顧成本與智慧

Clay 讓不同任務對應不同等級的 OpenAI 模型：主力模型是 GPT-6 Sol，處理 go-to-market 任務時有「很好的直覺」，能執行長時程、以結果為導向的工作；較困難的任務交給 GPT-6 Astra；成本敏感的工作則用 GPT-6 Luna。Jeff 特別提到，Responses API 讓這些不同價位的模型可以透過同一套介面呼叫，這對 Clay 來說「非常吸引人」。

GPT-6 Astra 也被用在 Clay 自己的工程流程上。Jeff 說，過去他得花大量時間手動檢查自己寫的功能，現在可以讓 Astra 寫程式、補上測試、實際執行測試，並把結果記錄進 PR，「完整閉環了整個工程流程」。

🎯 下一步：語音互動與決策 API

Jeff 也提到團隊正在探索的方向：用 GPT-Live-1 讓客戶能以語音方式透過 Clay 與 Codex 了解產品，並著手開發 inbound sales development 功能，讓 agent 主動向潛在客戶展示產品。他也將 Decisions API 視為把模型整合進 Clay、開拓新使用場景的另一條路徑。Clay 的目標，用 Jeff 的話來說，是把「軟體工程發生的那場轉變，帶到 go-to-market 領域」。

對正在設計 agent 工作流的工程師而言，Clay 的案例示範了一個實用模式：不要用單一模型打天下，而是依任務難度與成本敏感度，透過同一套 API 介面彈性切換模型等級。
