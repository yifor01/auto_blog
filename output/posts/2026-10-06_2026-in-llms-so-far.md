📌 標題: 從 Pelican 測試到 OpenClaw：Simon Willison 回顧 2026 LLM 大事記

TL;DR: Simon Willison 的年度回顧梳理了 coding agent 跨越可用門檻、OpenClaw 現象與「數位寵物」熱潮，勾勒出 2026 年 AI 工程生態的轉折點。

灣區的 Apple 門市一度把 Mac mini 賣到缺貨，原因不是什麼新品發表會，而是大家搶著買一臺機器來養自己的「數位寵物」。

🤔 背景：從兩個「剛好夠用」的模型開始

Simon Willison 在 WeAreDevelopers World Congress North America 的閉幕演講中，把 2026 年的 LLM 大事依時間順序串成一條線。故事的起點其實是 2025 年 11 月：Claude Opus 4.5 與 GPT-5.1 相繼發表。這兩個模型本身只是漸進式改進，但當它們分別搭配 Claude Code（2025 年 2 月上線）與 Codex 這兩套 coding agent 框架之後，整體表現跨過了一條無形的門檻，從「常常出錯」變成「可以每天依賴使用」。Willison 長期用「畫一隻騎腳踏車的鵜鶘 SVG」當作非正式評測，他提到當時 Claude 仍畫不出像樣的腳踏車，GPT-5.1 的車架也同樣慘不忍睹，說明即便 coding agent 開始可用，模型本身仍有明顯侷限。

🧩 OpenClaw 現象：一個 GitHub repo 的瘋狂成長

同樣在 2025 年 11 月，一個名叫「Warelay」的小眾 GitHub repo 悄悄提交了第一個 commit。到了隔年 1 月底，這個專案先後改名為 CLAWDIS、CLAWDBOT、Moltbot，最終定名為 OpenClaw，當時已累積 8,300 次 commit，距離專案啟動還不到兩個月；Willison 表示現在這個數字已經超過 10 萬次 commit，並稱它是「現存最 vibe-coded 的軟體」。這波浪潮也催生了一個新詞彙「Claw」，泛指這類個人化／通用型 agent 軟體，衍生出 NanoClaw、IronClaw、PicoClaw 等同類專案，如今也被重新包裝成「個人 agent」或「通用 agent」。Drew Breunig 的比喻很傳神：OpenClaw 像一隻數位寵物，而你買 Mac mini 只是為了給牠一個「水族箱」。

🧩 MoltBook：給 AI agent 用的社群網站

1 月也出現了 MoltBook，一個讓使用者把自己的 Claw 送去跟其他 Claw 互動的社群網站。Willison 描述這個專案在週四上線、週五就爆紅、週一被紐約時報報導，結果週二就被排山倒海的垃圾內容淹沒而被大家遺忘，一個月後被 Facebook/Meta 收購。

🧩 Dark Factory：StrongDM 的「不準人類寫程式」規則

2 月，StrongDM 提出「Software Factory」概念，描述一套高度自動化的軟體開發流程；Dan Shapiro 將這種做法稱為「Dark Factory」，意指工廠若足夠自動化，甚至可以關燈運作，因為不再需要人眼盯著生產線。StrongDM 自去年 7 月起遵循的第一條規則，就是「程式碼不可由人類撰寫」，任何程式碼都必須經過 coding agent 產出。

💡 深入分析：AI mania 與「AI 誘發的倦怠感」

Willison 也分享了個人經驗：今年他一反過去「保持專注、少接新專案」的新年目標，決定既然有了 coding agent，就盡量多接新專案來測試技術的極限。這也讓他陷入他自稱的「AI mania」，一種只要 agent 沒在幫自己做事就覺得時間被浪費的狀態，促使他寫出用 Python 打造的 JavaScript 直譯器（移植自 Fabrice Bellard 的 MicroQuickJS）與 Python 版 WebAssembly runtime 這類過度野心的專案；而在 Oxide and Friends 播客上，他和 Adam Leventhal 共同提出了另一個詞彙，形容「因為 AI 什麼都能做，工程師反而感到百無聊賴」的心理狀態，這個現象在多場會議演講中都被提及。

⚠️ 限制：預測並非全部成真

回顧年初在播客上做出的預測，Willison 坦言當時的預測其實偏保守：他預測 LLM 寫出好程式碼會變得「不容否認」，現在看來確實如此；他也預測 agent 安全的沙盒問題會被解決，而這次大會 277 場議程中約有 40 場觸及沙盒或 agent 安全議題，顯示業界確實投入大量心力，但他原本預測的「coding agent 被挾持、造成真實經濟損失」的重大事故並未真正發生。

🎯 實務啟示

這份回顧提醒工程師：coding agent 跨越「可日常依賴」門檻的時間點相對明確（2025 年 11 月前後的模型世代），值得作為評估團隊是否該全面導入 agent 工作流的參考座標；同時，agent 安全與沙盒化仍是業界持續投入但尚未完全解決的課題，在導入「Claw」類個人 agent 或 Dark Factory 式全自動流程前，應優先確認沙盒與權限邊界是否到位，而不是等事故發生才補救。
