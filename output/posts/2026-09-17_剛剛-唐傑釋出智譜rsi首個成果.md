📌 智譜唐傑曝光：GLM 已在優化承載自己的推理系統

TL;DR：GLM-5.3 驅動的 Infra Agent 自主優化生產推理系統，兩週內吞吐衝上初始基線的 3.2 倍，被視為 RSI 的早期工程雛形。

一個模型優化了執行自己的推理系統，這套被優化過的系統，又繼續承載新一代的它——這不是科幻設定，而是智譜創始人唐傑剛剛公開的內部觀察。

🤔 **從讀懂漏洞到參與構建 AI 本身**

唐傑提到，2025 年 10 月他們啟動安全能力增強研究時的判斷很樸素：能讀懂複雜程式碼的模型，應該也能理解程式碼中的漏洞。結果不到一年，安全夥伴用 GLM 在真實程式碼庫中發現了數千個漏洞，迫使團隊為此設計受信訪問計劃。而這次讓他更震動的變化是：GLM 開始越來越多地參與構建人工智慧本身。GLM-5.3-Flash 上線時，需要在超過 10 萬張國產晶片組成的叢集上從零搭建生產級推理服務，面對晶片記憶體容量與頻寬受限、模型需支援 1M 上下文與多模態請求、生態不成熟、運算元不完備等問題，而完成這件事的不是一支團隊，是 GLM-5.3 驅動的 Infra Agent。

🧩 **用「稠密反饋」把端到端指標拆解成可歸因訊號**

唐傑指出，Infra Agent 的工程效果不只取決於模型的程式碼生成與推理能力，更取決於系統能否持續提供有效、可歸因的反饋。單靠「精度測試未通過」或「吞吐下降 20%」這類稀疏訊號，Agent 難以判斷問題出在哪一層。團隊因此把正確性測試、執行日誌、執行 Trace、執行時事件、微基準測試與端到端指標都納入 Agent 的迭代流程，稱之為「稠密反饋」——反饋需要足夠局部、能低成本及時取得、且支援客觀驗證。整個優化閉環是：工程師定義目標與系統邊界，Agent 負責分析、假設與修改，實驗環境提供分層、及時且可驗證的反饋。最終形成的技術棧包含線性注意力與 LM Head 的節點內張量並行、ReplaySSM、W8A8 量化、INT8/FP8/BF16 混合精度快取量化、Layer Split，以及 Encode–Prefill–Decode（EPD）分離式架構。

📊 **三個案例：正確、找出瓶頸、跑得更快**

- **正確性反饋**：Agent 建立了推理引擎並行策略到運算元實現的對映，發現 KDA 運算元上下文並行（CP）路徑存在精度偏差——原因是 `tl.dot` 即使輸入 FP32 也預設用 TF32 計算，誤差在長上下文下累積放大。修復方式是將相關計算顯式指定 `input_precision="tf32x3"`，該精度修復已合併至 Flash Linear Attention 上游（PR #1180）。
- **系統行為反饋**：工程師設定 Prefill + KV Transfer 相對單獨 Prefill 的效能差距不應超過 5%，但 Agent 測出部分場景差距超過 20%。深入時間線分析後發現，DeepEP v1.2.1 的 intranode_dispatch/combine 沒有釋放 Python GIL，導致負責 Mooncake Transfer 的 Python 執行緒無法及時搶到 GIL、傳輸排程被推遲。修復後，Prefill + KV Transfer 與單獨 Prefill 的效能差距壓到 1% 以內。
- **效能反饋**：KDA Decode 運算元導入 ReplaySSM（以算換存）後第一版反而變慢，Agent 先靠除法最佳化縮短 9.6% 執行時間，接著發現原實現沿 V 維度分塊導致相同的 FP32 歸一化與門控計算被重複執行四次，於是合併分塊、提前批次計算並共享中間結果，換來 1.71 倍的效能提升。

整體而言，GLM-5.3-Flash 不到兩週內完成從模型適配到生產可用的跨越，端到端吞吐提升至初始基線的 3.2 倍；上線一週便在 OpenCode 與 OpenRouter 上以匿名模型「Ox-Alpha」成為雙平臺調用量最大的模型，6 天 token 調用量超過 62 萬億。

💡 **模型優化系統，系統承載模型**

唐傑把這個套娃式的閉環概括為一句話：模型優化系統，系統承載模型。他也坦言，這距離「AI 完全自主設計並訓練自己的繼任者」（Recursive Self-Improvement, RSI）還很遠——目標怎麼定、邊界怎麼劃、風險怎麼判斷，目前仍由人類工程師負責，智譜自己也明確強調尚未實現 RSI。但這次分享的價值在於，RSI 第一次有了工程化、且已跑進生產環境的雛形，而不只是抽象討論。

🎯 **實務啟示**

對正在建置 Infra Agent 或自動化系統優化流程的工程師來說，這篇分享的核心方法論值得借鏡：把「正確性反饋、系統行為反饋、效能反饋」分成三層，各自對應「算得對不對」「時間花在哪」「哪個方案在什麼條件下更好」，能讓 Agent 從稀疏的端到端指標中真正定位問題根因，而不是盲目試錯。
