📌 具身智慧的「最後一哩路」：清華、上海交大攜手開源機器人端側推理引擎 APXInf

TL;DR：清華、上海交大聯合開源機器人端側推理引擎 APXInf，延遲大砍逾十倍。

具身模型在雲端測試時表現亮眼，一旦真正部署到機器人本體上，第一個攔路的往往不是「模型夠不夠聰明」，而是推理系統本身撐不撐得住，能不能秒開機、能不能榨乾有限的端側算力、延遲會不會拖垮動作的連貫性。無問芯穹與清華大學、上海交通大學今天正式開源了針對這個問題設計的具身智慧端側推理引擎：APXInf。

🤔 雲端推理框架直接「搬」到機器人本體行不通

文章指出，具身智慧從「看懂環境、理解指令」走到「規模化落地」，中間必須完成一個從感知到決策再到動作的極短時間閉環。對雲端聊天機器人而言，幾百毫秒延遲頂多是體驗上的落差；但對需要持續感知、連續決策與即時控制的機器人來說，同樣的延遲可能直接造成動作遲滯、軌跡不連貫，甚至任務失敗。再加上算力成本、功耗與硬體資源利用率的現實考量，現有方案往往顧此失彼：有的跑得快但需要大量底層適配整合，有的執行穩定卻滿足不了即時控制所需的低延遲，還有的介面簡單卻難以應付不斷變化的 VLA 模型架構與硬體組合。APXInf 想解決的正是這種「效能」與「工程效率」很難兩全的問題。

🧩 快、穩、敏捷：三個設計主軸

APXInf 圍繞機器人真實執行鏈路做端到端最佳化，透過 Pipeline、Graph、Kernel 以及量化等多層最佳化降低推理延遲，並搭配 Agent4Kernel 技術產出極致最佳化的融合運算元。同時，它採用 Rust 系統語言打造的極簡執行時，搭配 Python 易用介面封裝，利用 Rust 的記憶體安全特性從源頭降低出錯機率，並透過冗餘特性設計讓執行時可核查、可驗證，兼顧底層硬核效能與上層開發者熟悉的呼叫方式。

在「敏捷」這個面向，APXInf 從設計之初就以適配 Agentic Engineering（讓 AI coding agent 參與研發流程）為出發點，透過冗餘特性、功能隔離、工具箱模型等方法降低新模型接入與最佳化的門檻。團隊的說法是，希望 APXInf 不只是被動執行模型的 runtime，而是連接模型、硬體、機器人與開發者的基礎設施，朝「Agentic Native」的推理系統範式演進。

📊 PI 0.5 延遲從 278ms 降到 26ms 以內

在 Jetson Thor 上，APXInf 把 PI 0.5 FP8 的端到端推理延遲從 278ms 降至 26ms 以內，換算下來推理頻率可達 38.46Hz，相當於延遲下降了 10.7 倍。文章強調，這樣的延遲降幅意味著機器人「感知—決策—動作」的閉環能跑得更快，具身模型也更有機會在真實機器人上進入即時工作狀態。

💡 支援三大硬體平臺，並銜接訓練框架 RLinf

APXInf 支援 RTX 4090、Jetson Orin、Jetson Thor 等主流計算平臺，並提供統一的模型接入方式，涵蓋從模型開發、效果驗證到機器人本體部署的完整鏈路。首發支援的模型是 PI 0.5 與 WALL-OSS；原始碼與 Quick Start 文件已公開在 GitHub 的 RLinf/APXinf-robo 專案。

無問芯穹與清華大學團隊在 2025 年 9 月已開源全球首個面向具身智慧的大規模強化學習訓練框架 RLinf，專為透過強化學習對具身大模型做後訓練而設計。APXInf 則把這條技術鏈路從模型訓練與評測，延伸到機器人端側推理與部署，讓開發者能沿著同一套生態，走完從訓練、效果驗證到本體部署、真實機器人執行的完整流程。

Roadmap 上，團隊預告將持續擴充支援的模型（VLA、VLM、世界模型，Qwen、Groot 已在適配中）、做極致的 nvfp4 效能最佳化，並拓展對國產晶片算力後端、國產機器人作業系統以及 AMD 等主流晶片的支援。

🎯 實務啟示

如果你正在把 π0.5 這類具身模型部署到 RTX 4090、Jetson Thor 或 Orin 等硬體上，或正在為自研的 VLA 模型尋找端側推理引擎，APXInf 提供了一條可以直接試跑、送 Issue 或貢獻 PR 的開源路徑。對整個具身智慧領域而言，這也是一個訊號：當模型能力逐漸成熟，卡住規模化落地的瓶頸正在從「模型好不好」轉移到「端側推理系統撐不撐得住」。
