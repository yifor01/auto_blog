📌 Claude Code大重構：協調器一聲令下，AI自己開分支寫程式碼

TL;DR：Claude Code Projects重構為多Agent協作中樞，Anthropic內部揭露26%研發任務已交給AI自主完成。

Git分支、PR、合併衝突，這些原本是工程師的日常操作。現在，Anthropic直接把這套流程交給了AI自己跑。

🤔 從「靜態資料夾」到「對話驅動的協作中心」

過去Claude Code的Projects功能，本質上只是存放提示詞和參考文件的資料夾，聊上幾輪上下文就容易亂掉。這次重構把形態徹底改變：Projects變成一個以對話為驅動的協作中心，核心是一個名為Coordinator（協調器）的角色。開發者只需在主對話丟出高階目標，例如「把整個鑑權模組重構為OAuth 2.0並補齊自動化測試」，剩下的拆解與排程交給協調器處理。

🧩 每個子任務都是一個雲端Claude Code例項

協調器接到指令後，會把複雜工程任務拆解成多個子任務，分派給並行的工作執行緒。每個工作執行緒都是一個執行在雲端獨立環境裡的Claude Code例項，擁有完全隔離的程式碼副本，各自拉出獨立的Git分支，同時推進不同模組的程式碼編寫與單測，完工後自動在後臺提交程式碼並生成PR。過去多Agent各寫各的容易造成上下文傳遞損失、Token浪費,這次A社給出的解法是共享記憶:所有分支執行緒沉澱的技術規範、架構決策與團隊偏好都會即時同步回共享記憶,讓Claude記得系統釋出時間改到了週五、匯出功能為什麼被取消、訪問帳單服務前該聯絡誰。整個流程支援完全非同步,開發者合上電腦也能讓執行緒繼續跑,並透過行動端檢視進度、微調指令。目前功能仍是beta,第一批僅開放部分Claude Pro與Max訂閱、且使用雲會話專案的使用者,後續一週逐步放量。

📊 半年時間，AL4級研發佔比從不到1%衝到26%

同一時間,Anthropic在《衡量AI研發節奏》報告中首次公開內部AI自主研發基準資料。依前沿機構Epoch AI制定的AL0至AL5自動化分級標準(AL0為純人類操作,AL3為深度人機協作,AL4代表AI能憑一句高階指令端到端完成任務,AL5為完全脫離人類干預的自主閉環),Anthropic內部目前AL4級研發任務佔比達26%,而今年2月這個數字還不到1%。若把標準放寬到AL3,內部超過90%的研發流程已達到這個門檻。支撐這一切的,是A社內部研發平臺上截至今年8月常態化併發執行的多達30000個AI Agent,單月觸發的決策量超過10億次。公司稱配備了全天候即時監控系統(Agent Oversight)動態審查所有AI操作,在8月超10億次模型決策中攔截了約0.002%的高風險或異常行為。此外,7月13日至20日期間,公司約6%的AI研發算力花在安全與對齊研究上,同一週AI驅動型研發算力中約12%投向安全相關任務。

💡 工程師的角色正在往上移

從內部30000個Agent單月觸發10億次決策,到外部產品支援多分支併發提交PR,寫程式碼這個動作本身正在迅速貶值,工程拆解與任務排程能力成了核心競爭力。過去一個中級工程師在終端裡一次只能死磕一個特性,現在一個人可能同時帶著一群Claude Code開工,角色從逐行敲程式碼的執行者,變成拍板架構方向、稽核PR、處理異常邊界的技術負責人。當然多分支並行並非萬能,重疊修改依然會撞上Git合併衝突,協調器會理清依賴關係,但最終仍需要人類工程師介入把關。值得一提的是,9月10日Cursor也發布了Projects beta,同樣主打不寫程式碼的Coordinator Agent向下派發數千個子Agent,顯示這並非A社一家的判斷。

🎯 實務啟示

如果你的團隊已經在用Claude Code處理較大範圍的重構任務,可以開始留意任務拆解與依賴排程的設計,而不是繼續把AI當成單一對話裡的程式碼補全工具。同時也要留意多Agent並行的Token消耗,官方也提醒使用者隨時關注usage。
