📌 Simon Willison 的 Coding Agents 使用指南  

你有試過讓 Claude Code、OpenAI Codex 幫你寫出完整功能，卻發現除錯變得更困難？這份指南告訴你該怎麼避免常見陷阱，讓 AI 真正成為你的得力助手。  

🤔 **為何需要這份指南**  
隨著 coding agent 成為開發者日常工具，許多團隊發現單纯依賴 AI 產出程式碼並不等於提升開發效率或品質。缺乏系統化的使用模式，容易陷入「AI 寫、人除錯」的惡性循環。Simon Willison 因此編寫了這份實戰指南，希望提供一套可直接套用的模式，幫助工程師在使用 coding agent 時保持程式碼品質與自身學習成長。  

🧪 **指南的編寫方式與章節架構**  
這份指南共分為 16 個章節，每個章節圍繞一個具體的使用模式或常見問題進行說明。章節標題包括：

每個章節都以實際操作步驟或範例程式碼為基礎，讀者可以直接對照自己的工作流程進行練習。  

💡 **指南提供的實用模式**  
核心內容可歸納為三類模式：  
1. **預防性最佳實踐** – 例如「先跑測試」、「使用 Git 追蹤變更」、「採用 Red/green TDD」等，確保 AI 產出的程式碼在納入版本控制前就經過基本品質檢查。  
2. **進階互動技巧** – 如「Linear walkthroughs」、「Interactive explanations」與「Subagents」，教你如何透過逐步提問或分解任務，讓 AI 在解釋邏輯時更透過、在處理複雜流程時更有條理。  
3. **避免的反模式** – 特別列出應該避免的情況，例如過度依賴 AI 進行除錯而不理解錯誤根因，或直接將 AI 產出的程式碼合併而未進行人工審閱。  

🔍 **深入分析：這些模式為何有效**  
指南背後的假設是：coding agent 產出的程式碼在語法上往往正確，但在語意上仍需要人類的判斷來確保符合業務需求與可維護性。透過「先跑測試」與「Red/green TDD」，開發者可以在 AI 產出後快速驗證功能是否符合預期；透過「Interactive explanations」則能迫使 AI 在給出程式碼時同時說明設計決策，這有助於開發者建立對程式的理解，而非只是複製貼上。  
同時，指南強調「Hoard things you know how to do」——將已經熟悉的小工具或腳本納入個人知識庫，讓 AI 在需要時可以呼叫這些可信任的組件，減少對未經驗證的產出的依賴。  

⚠️ **指南的使用限制**  
- 內容基於 Simon Willison 個人在使用 Claude Code 與 OpenAI Codex 時的實踐經驗，並未透過對照實驗或統計分析驗證。  
- 某些章節（例如「GIF optimization tool using WebAssembly and Gifsicle」）屬於特定領域的示例，可能不直接適用於所有類型的專案。  
- 指南主要聚焦於 prompt 工作流與版本控制的結合，未涵蓋模型微調或訓練層面的議題。  

🎯 **實務啟示：如何在團隊中落實**  
- 將「First run the tests」與「Using Git with coding agents」納入團隊的 Definition of Done，確保每一次 AI 產出的程式碼都經過自動測試與版本控制的檢查點。  
- 鼓勵開發者在使用 AI 時採用「Linear walkthroughs」或「Interactive explanations」的習慣，變成「先讓 AI 解釋，再決定是否採用」的決策流程。  
- 建立內部的「Prompts I use」知識庫，讓團隊成員共享已被驗證有效的提詞範本，提高整體使用一致性與效率。
