📌 KV 快取壓到常數：百度開源 OCR 新王，連讀千頁不卡記憶體

TL;DR：文心 Unlimited OCR 2 用 SR-SWA 把長文件 KV 快取砍 96%，開源可用。

讀完一整套《哈利波特》7 冊、3600 多頁，中間不停頓；換成《三體》全集 1200 多頁，一樣一口氣讀完。這不是人類的閱讀速度比拼，而是百度剛開源的文心 Unlimited OCR 2 要解決的問題：模型要連續解析超長文件,最大的敵人不是識別準確率,而是 GPU 記憶體。

🤔 **文件越長，模型要記的「小抄」就越厚**

文件越長，推理時需要保留的中間資訊（KV 快取）就越多,可以理解成模型邊讀邊記的小抄。頁數一多，小抄不只佔空間,翻找也變慢。上一代 Unlimited OCR 已靠多頁連續解析能力,累積超過 1000 萬次下載、GitHub 近 2.86 萬顆星,但到了幾百頁等級的文件,計算與快取負擔仍會隨頁數線性增加。

🧩 **SR-SWA：先篩頁面,再篩段落**

文心 Unlimited OCR 2 借鑑人類抄書的思路:眼睛主要盯著正在抄的那一頁,只有遇到需要前後對照時才回頭翻頁,不會把全書攤開同時看。整體架構上,書頁影像先經 DeepEncoder 轉成視覺 token,語言模型再依此逐步生成識別結果。

關鍵升級在語言模型內部:上一代的「參考滑動視窗注意力機制」(R-SWA) 升級為「稀疏參考滑動視窗注意力機制」(SR-SWA),分兩層篩選。第一層 Page Gate 依目前解析的位置,把候選視覺資訊收攏到相關頁面範圍內,擋掉無關頁面;第二層 Token Sieve 在篩出的頁面裡,先用簡要表示算出相關性,再用 TopK 挑出得分最高、數量固定的視覺資訊塊,捕捉長距離視覺依賴。篩選出的資訊,還會與一個大小固定、隨生成過程向前平移的 Local Window(局部滑動視窗)一起參與解析。因為篩選後的資訊量與局部視窗大小都是固定的,文件再長,每一步要處理的運算量也不會增加。

少算之外,還要少存。團隊引入「無限解碼機制」(Unlimited-Horizon Decoding Paradigm),把文件切成大小可控的頁面塊依序處理,相鄰兩塊重疊一頁作為銜接點。進入下一塊時,直接複用重疊頁的視覺 KV 快取,同時保留上一段輸出末尾的文本快取,其餘用不到的頁面視覺快取則即時釋放,讓 GPU 記憶體裡只留著當前處理塊規模的資訊。

📊 **47GB 降到 1.77GB,併發吞吐漲 3.65 倍**

在團隊新建的百頁級基準 MarathonDocBench(100 份文件,每份 103 至 300 頁)上,單序列推理的峰值 KV 快取從標準解碼的 47GB 降到 1.77GB,降幅約 96%。在 16 路併發測試中,端到端吞吐量從 360 提升到 1315 token/秒,約為標準解碼的 3.65 倍。單步解碼速度上,SR-SWA 是全注意力機制的 7.0 倍、上一代 R-SWA 的 5.6 倍,且隨文件變長幾乎維持水平線,不會因為書越厚而寫字變慢。

識別品質上,MPDocBench(多頁文件解析)拿下 84.59 分,MarathonDocBench 拿下 77.06 分,兩項測試中都是報告列出模型裡的最高分。團隊也實測一本 884 頁的英文版《魔戒》,42 分 56 秒解析完成,平均每頁約 2.9 秒;抽查第 600 頁與第 750 頁,識別文字與原文一致;整個任務中系統標記了 466 處跨頁合併,例如接近書末被分頁截斷的句子,也在輸出中重新接回。

💡 **從 OCR 1.0 到 3.0 的演進**

團隊把文件解析的演進分成三階段:OCR 1.0 是偵測、識別、排版各自獨立的流水線,逐頁處理再拼接;OCR 2.0 是視覺語言模型端到端生成解析結果,上一代 Unlimited OCR 把這種端到端能力擴展到數十頁;而這一代把「持續處理整份文件」作為目標,團隊稱之為 OCR 3.0。模型名稱 Unlimited OCR Works 致敬《Fate/stay night》的「無限劍制」(Unlimited Blade Works),社群用戶 Snarcy 曾把原作詠唱改寫成 OCR 版本,這次也被收進技術報告引言並保留署名。

⚠️ **適用場景與留意點**

這套機制最適合批次處理年報、技術手冊或掃描件等長文件場景,使用者不需手動拆頁再拼接,分塊與銜接由模型內部完成。需留意的是,1.77GB 的快取數字僅指 KV 快取本身,模型權重等其他 GPU 記憶體開銷另計。

🎯 **實務啟示**

對要批次跑長文件 OCR 或 RAG 前處理的團隊,文心 Unlimited OCR 2 的 SR-SWA 思路值得參考:把「全文件全注意力」換成「按需參考 + 分塊釋放快取」,同一塊 GPU 能塞進更多任務,併發吞吐也同步提升。模型已在 GitHub 與 Hugging Face 開源,可直接測試既有的掃描文件場景。
