📌 【Meta Reality Labs 與華盛頓大學團隊】小模型一定比較快？輸出 Token 數量才是推論瓶頸

業界部署 VLM 時，常直覺認為「模型越小，推論越快」。但最新實證指出，真正拖垮延遲的其實是「輸出長度」。當小模型需要產生長串文字才能解題時，其端到端延遲反而可能超過只需精簡回答的大模型。

🤔 **推論加速的盲點：我們過度關注參數量，卻忽略了輸出代價**

目前主流的視覺語言模型 (VLM) 普遍採用自回歸 (Autoregressive) 解碼器，逐個產生回應 Token。這意味著輸出序列長度會直接線性影響端到端延遲。在追求邊緣部署或降低成本的趨勢下，工程團隊常傾向選擇參數量較小的模型。然而，不同架構解決同一任務所需的輸出長度差異極大。若小模型必須產生大量文字才能達到與大模型相近的準確率，其推論效率反而會因解碼步驟過多而劣於能精簡輸出大模型。忽略「輸出代價」而只看模型大小，是當前效能優化常見的誤區。

🧪 **跨模型延遲剖析與多智能體架構驗證**

研究團隊首先在模擬環境中進行各組件延遲剖析，量化確認輸出 Token 數量是 VLM 的效能瓶頸。隨後在多項真實基準測試中，系統性比對不同規模模型在相同任務下的輸出長度與最終表現。為驗證效率潛力，論文設計了一套多智能體推論框架：系統預設維持大模型的短回覆模式，但在任務需要複雜邏輯時，動態呼叫小模型生成關鍵推理路徑，並將這些推理 Token 轉移注入，作為大模型後續生成的引導條件。

📊 **大模型生成少量 Token 的延遲，可能低於小模型的長文本輸出**

實驗結果明確驗證了反直覺的結論：在達成相近或更優任務表現的前提下，使用較少輸出 Token 的大模型，其端到端延遲顯著低於需要長篇輸出小模型。更重要的是，透過多智能體框架引入小模型的推理 Token 後，系統能在不增加大模型自回歸生成步數的情況下，逼近大模型獨立完成完整推理時的準確率。這證明了「減少輸出步數」對推論效率的提升，往往大於「縮減模型參數」帶來的收益。

💡 **讓小模型提供推理路徑，大模型聚焦精準生成**

這項設計的核心機制在於將「推理路徑探索」與「語言生成」解耦。小模型雖然整體能力較弱，但仍具備基礎的邏輯推演能力，可用於快速產出結構化的中間推理 Token。將這些 Token 直接作為 Prompt 或 KV Cache 條件注入大模型，等同於為大模型提供已驗證的思考草稿，大幅削減大模型需要自行探索與修正的解碼步驟。這不僅是單純的模型融合，更是一種針對自回歸機制的 Token 經濟學優化，為高延遲敏感場景提供了新的架構思路。

⚠️ **尚未開源且依賴 Token 對齊機制，實作複雜度待驗證**

該研究目前屬概念驗證階段，暫未釋出開源程式碼。實務上，多模型間的 Token 轉移涉及語意空間對齊、上下文長度管理與動態路由策略，工程實作門檻不低。此外，實驗主要基於標準基準任務，不同垂直領域的推理路徑是否都能被有效壓縮與無縫轉移，仍需更多長尾場景驗證。

🎯 **部署 VLM 時，應將「輸出長度預估」納入模型選型核心指標**

對於 MLOps 與系統架構師而言，模型選型不應僅依賴 FLOPs 或參數量排名。在規劃部署前，應針對目標任務進行「平均輸出 Token 長度」的壓力測試。對於需要高準確率且延遲敏感的應用，可評估此類跨模型 Token 轉移架構，或優先選擇具備「精簡輸出」特性的架構設計。與其盲目追求小模型部署，不如將推論管線轉向「小模型負責探索路徑、大模型負責收斂輸出」的分工協作模式。
