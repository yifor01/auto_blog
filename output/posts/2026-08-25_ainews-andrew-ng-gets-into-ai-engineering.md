📌 Andrew Ng 重新出手：AI 工程師該練的是這四項技能

TL;DR：分析上萬筆職缺後，DeepLearning.AI 重新聚焦 AI Engineering，列出四項核心技能。

當「AI 時代到底該練什麼技能」這個問題連 Google Brain 共同創辦人都要跑去分析一萬份職缺才敢回答，這件事本身就值得工程師停下來看一眼。

🤔 **從一萬份職缺裡挖出來的答案**

Latent Space 報導，Andrew Ng 重新啟動 DeepLearning.AI，聚焦在「AI Engineering」這個方向。方法論相當紮實：分析超過一萬份職缺公告、與 AI 專家／招聘經理／獵頭進行數十次結構化訪談、透過問卷收集資料，再綜合其他線上資料。

🧩 **四項技能，一項比一項貼近實戰**

第一項是「建構與部署 AI 應用」：理解 LLM、context engineering、RAG、agentic workflows 等基礎元件，並懂得用統計方法測量、引導、治理 AI 系統的行為，核心能力是能跑得動有紀律的 eval 與錯誤分析迴圈。這部分最貼近傳統 MLE／MLOps 的工作內容。

第二項是「軟體工程基本功」：理解軟體工程的基礎，才能看懂技術選型、系統架構、資料儲存設計、測試等地方到底存在哪些取捨。Ng 特別點出，這也是為什麼經驗不足的開發者「vibe coding」出來的結果常常較差——因為他們不知道該給 coding agent 什麼上下文，agent 也就在看不見的地方做出了糟糕的取捨。

第三項是「善用 coding agent」：對 agent 如何運作要有正確的心智模型，理解其限制與變通方法，知道該介入多少、放手多少，並且要懂得何時該寫清楚的 spec、何時不必，還要能協調多個 agent 協同工作，避免讓 agent 誤觸生產環境資料庫這類地雷。由於 agentic coding 演進飛快，這項技能也意味著要持續嘗試新工具、跟著最佳實踐演化工作流程。

第四項是「參與塑造產品方向」：具備產品直覺，理解商業脈絡與客戶目標，才能參與並主導專案推進，包括判斷何時該快速做出 MVP 拿去讓使用者測試、何時該放慢腳步謹慎打磨。

💡 **LLM 拉高天花板，而非拉高地板**

Latent Space 的評論一針見血：LLM 對高技能開發者的提升幅度，遠大於對低技能「vibe coder」的提升，雖然兩者都有進步，但差距在拉大。這也呼應了同一份 newsletter 裡觀察到的另一個趨勢——agent harness（而非底層模型本身）正成為決定 agent 品質的主要優化戰場，企業級 MCP 的權限管理與長時間工作流支援也正在成熟，這些都指向同一件事：能不能把 agent 用好、用穩，正在變成比選哪個模型更重要的能力。

🎯 **實務啟示**

對工程師而言，與其糾結該不該用 AI 寫程式，不如把力氣放在四件事上：建立扎實的 eval 與錯誤分析習慣、補齊軟體工程基本功、持續打磨與 coding agent 協作的直覺、以及主動理解自己在做的功能到底為誰、為何而做。這四項技能的組合，比單一職稱「AI Engineer」適用範圍更廣。
