📌 國產團隊獨立重現Jev決策範式，筆電也能跑瀏覽器自動化

TL;DR：APUS 開源 fast-browser-use，用本地模型重現Jev的快速決策邏輯，離線就能操作瀏覽器。

當各家都在比拼大模型能寫多長的推理鏈時，APUS AI 實驗室選擇了反方向的題目：讓決策快到不需要推理鏈。

🤔 **Jev是什麼，為何叫「決策模型」**

Jev之名取自19世紀經濟學家傑文斯（Jevons），呼應「傑文斯悖論」：智慧使用成本暴跌，將帶來智慧用量暴漲。這類模型鎖定 Agent 執行過程中最高頻的需求，也就是分類、選擇、評分、真偽判斷，直接回傳型別化答案與置信機率，而不是逐字生成文字。業界因此把 Agent 架構拆成「快慢分工」：昂貴的大模型負責規劃等「慢思考」，高頻、原子化的「快判斷」交給輕量決策模型完成；負責組裝與排程這套分工的工程層，則被稱為 Harness。

🧩 **APUS重現了核心機制，並落地到瀏覽器自動化**

APUS基於Jev公開文件展示的輸入範式與評估邏輯，分析出其「跳過自迴歸解碼、隱狀態直接打分」的核心邏輯，並在開源專案中重現了單 Token Logits 快速決策、Jev 的 KV-Cache 廣播，以及併發批次評估的運作機制。

在瀏覽器自動化場景中，fast-browser-use 會把頁面上真實可見、可互動的元素整理成帶編號的候選動作集合，交由本地執行的 Qwen3.5-9B 模型以單次前向計算直接完成「點哪裡、選哪個」的判斷，從機制上消除模型生成錯誤選擇器或格式幻覺的可能。整個專案支援 macOS、Linux、Windows 三大主流桌面與伺服器作業系統，既能在 GPU 伺服器上執行，也能在沒有 GPU 的 Mac 與 PC 上跑，全部程式碼以 MIT 授權開放。

📊 **實測：一臺 M2 Pro 筆電，中位18秒完成維基百科檢索**

APUS 公佈的實測資料顯示，在一臺 Apple M2 Pro 消費級筆記型電腦上，Agent 依靠本地模型推理，全程離線完成真實維基百科檢索任務的中位耗時約18秒；表單填報、站內導航等任務耗時僅約3秒，單一任務的模型打分次數僅4次，全程零雲端呼叫、零 API 費用，使用者資料不會離開本機。

💡 **開源復現的三重意義**

APUS AI 實驗室表示，這次開源復現有三重意義：其一，驗證「用模型做 Harness」這條技術路線在工程上的可行性；其二，證明在閉源 API 之外，開源權重加端側算力同樣能支撐這種範式，且資料全程留在本機，滿足政企與金融場景對資料安全的要求；其三，為業界提供一份資料透明、程式碼可覆核的獨立驗證參考——此前 Jev 的效能資料都僅來自 TypeSafe 官方自測。

fast-browser-use 已封裝為標準 Agent Skill，開發者可透過一行指令接入 Claude Code、Codex、OpenCode 等主流程式設計 Agent。APUS AI 實驗室也表示，後續將圍繞桌面 GUI 操作、本地作業系統互動等場景持續開源新的 Skill。

🎯 **實務啟示**

對於重視資料主權、又需要高頻率原子決策的場景（例如 RPA、瀏覽器自動化、企業內部工具），這個方向提供了一條不依賴雲端 API 的路徑：把「快判斷」下放到本地小模型，只在真正需要複雜推理時才呼叫大模型，能同時降低延遲與成本。
