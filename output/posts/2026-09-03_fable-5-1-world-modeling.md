📌 一句話輸入，就能生成可走進去的 3D 城市：Fable 5.1 智慧體群把「世界」寫成程式碼

TL;DR：開源專案 fable51-worlds 用 Claude Fable 5.1 智慧體群，把一句話、一張照片或一段影片轉成可在瀏覽器漫遊的真實場景。

一個地址、一張照片，或是一段三十秒的走拍影片，能不能直接變成一個你可以走進去逛的 3D 世界？這個在 Hacker News 拿下 322 點讚、93 則討論的開源專案 fable51-worlds 給出的答案是：可以，而且輸出的不是一堆預先烘焙好的網格資源，而是一整套會自己畫出建築、招牌、樹木、紅綠燈的程式碼。

🤔 「世界即程式碼」要解決什麼問題

README 開宗明義寫道：「Worlds as code. A prompt in, a world you can walk out.」專案讓 Claude Fable 5.1 智慧體群接收一份簡報（brief）——可以是一句話、一張照片或一段影片——研究這個地點、建模、渲染、再自我檢查，最終輸出一個純 Three.js 應用程式，直接在瀏覽器打開即可漫遊，不依賴任何遊戲引擎、不用專有的 3D 圖磚（3D tiles），也不下載現成的網格資源；每一棟建築、每一間店面、每一塊招牌、每一棵樹、每一盞紅綠燈，都是由這個 repo 裡的程式碼即時生成的。目前已展示的作品包括舊金山 Union Square 廣場與京都東山（從祇園到清水寺的黃昏場景）。

🧩 從一句簡報到一個世界：四道生產線

README 詳細列出了每個階段，且每個階段都能重新執行：
- 偵察（Reconnaissance）：多個平行研究智慧體拉取地圖幾何、地形高程、大眾運輸與街道規格，以及店面普查資料，每一項事實都附帶來源與信心水準。
- 資產生成（Asset generation）：腳本產出世界所需的套件，包括立面模組、街道傢俱、車輛、植栽、燈具；部分世界甚至不出貨任何二進位資產，所有貼圖都在啟動時即時繪製。
- 執行時（Runtime）：一個純 Three.js 應用程式依據 JSON 規格，組裝地形、街道、立面、道具、人群與交通。
- 驗證（Verification）：Playwright 驅動實際的應用程式，在固定視角截圖，並與同一地點拍攝的照片做差異比對；獨立的審核智慧體（建築師、地理學家、技術美術、互動設計）各自撰寫報告，驅動下一輪修正。README 特別強調「建造者不能自己批改自己的作業」，每個世界都會附上自己的 QA 報告，包含瑕疵清單。

🧩 三種輸入方式，同一套管線

專案支援文字、影片、圖片三種輸入形式，走的都是同一套生成管線：文字簡報（例如「京都花見小路，畫成手繪動畫背景風格」）指名地點與風格，會得到「架在實測地面上的真實幾何，配上訂製的畫風」；一段三十秒的走拍影片，能還原出鏡頭之外的整個場景，讓你走出攝影機路徑繼續探索；一張照片則能還原出畫面中地點的幾何結構，讓你轉身、改變時間、換一種打光方式。風格與主題一樣開放，同一條街可以是賽璐璐動畫、寫實重建，或是夜景，因為每個世界的渲染器都是量身撰寫的，而非從清單裡挑選。

💡 為什麼要「寫成程式碼」而不是生成像素

README 給出三個理由：可驗證（每個東山的高程都是獨立測量查詢，Playwright 會拿固定視角截圖跟同地點照片做比對，數字錯了就是測試失敗，不是美感問題）；可組合（房屋生成器、屋頂套件、街道地塊排版引擎，各自是有明確介面的模組，一個街區只需幾百行程式碼呼叫它們）；可編輯（「把店面凹進去做深一點」是一筆 diff，不是重新生成一次，變動只會發生在你要求的地方，且會延續到之後所有的渲染結果）。

⚠️ 目前的範圍與授權注意事項

README 的 Roadmap 顯示，目前已完成的只有「互動場景」（本 repo），動畫與影片、智慧體訓練評估環境、4D 與具身機器人模擬都還在規劃中。授權部分，程式碼與生成的資產採 MIT 授權，但幾何資料衍生自 OpenStreetMap（ODbL 授權）、USGS 3DEP 與 GSI 高程服務，需留意 ODbL 的分享方式限制；參考照片本身不會被收錄在 repo 中，只會記錄來源；品牌名稱與商標則屬於真實商家所有。

🎯 實務啟示

如果你在做地理空間模擬、遊戲美術資產生成或機器人訓練環境，這個專案示範了一個值得借鏡的思路：與其讓智慧體直接吐出像素或網格，不如讓它寫出「可重跑、可驗證、可 diff」的生成式程式碼，配合自動化視覺比對做 QA，這對需要長期維護與迭代的場景資產管線特別有參考價值。但也要留意，目前僅涵蓋靜態互動場景，動態與具身模擬能力仍待專案後續釋出。
