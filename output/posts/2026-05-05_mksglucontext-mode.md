📌 Context Mode 解Agent上下文难题

MCP 工具确实扩展了 Agent 能力，但它的隐藏成本你算过吗？一次 Playwright 快照占 56KB 上下文，20 个 GitHub issue 吃掉 59KB，跑满 30 分钟，你的上下文窗口已经空了 40%。

🤔 **MCP 工具調用正快速消耗上下文窗口**
當前 MCP 工具調用會將原始數據直接塞入上下文窗口，單次 Playwright 快照就會佔用 56 KB 空間，20 個 GitHub issue 佔用 59 KB，單個訪問日誌也會消耗 45 KB。運行 30 分鐘後，40% 的上下文空間就會被佔用。當 Agent 壓縮對話以釋放空間時，會遺忘正在編輯的文件、進行中的任務、用戶最後的請求。此外 Agent 還會在客套話、冗長解釋上浪費輸出 token，從輸入輸出兩側同時消耗上下文空間。

🧪 **三項核心機制解 MCP Agent 上下文痛點**
Context Mode 是針對上述問題設計的 MCP 服務器，核心機制包含三項：
1. 上下文節省：透過沙箱工具將原始數據擋在上下文窗口外，315 KB 原始數據可縮減至 5.4 KB，實現 98% 的上下文佔用降低。
2. 會話連續性：所有文件編輯、git 操作、任務、錯誤、用戶決策都會存入 SQLite 數據庫。當對話壓縮時，不會將這些數據重新塞入上下文，而是透過 FTS5 索引事件，透過 BM25 搜索檢索相關內容，讓模型精準接續之前的進度。若選擇不繼續上次會話，舊會話數據會立即刪除，新會話保持乾淨。
3. 程式化思考：引導 LLM 透過寫腳本完成分析，而非將大量文件讀入上下文。例如要統計 50 個文件的函數數量，只需讓 Agent 寫一個腳本執行並輸出結果，一個腳本可替代十次工具調用，節省 100 倍上下文空間。
