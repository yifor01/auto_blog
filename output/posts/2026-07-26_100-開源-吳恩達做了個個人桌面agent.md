📌 【吳恩達開源新作】OpenWorker：不只是聊天機器人，是能直接交付成果的 AI 同事

TL;DR：吳恩達推出開源桌面 Agent OpenWorker，主打本地優先與多工具整合，實現從「對話」到「交付成果」的跨越。

當大家還在討論如何與 LLM 進行更有深度的對話時，AI 教育巨頭吳恩達（Andrew Ng）已經把目標鎖定在「交付成品」上。他最新推出的開源專案 OpenWorker，不再只是停留在「建議」或「列出清單」，而是試圖成為一個能跨越不同軟體、直接幫你把工作做完的「AI 同事」。

🧩 **核心設計理念：開放、本地優先與模型無關**

OpenWorker 的設計核心在於打破目前 AI 工具的限制，主要具備四大特性：
- **完全開源**：採用 MIT License 授權。
- **本地優先與隱私保護**：除非使用者主動選擇使用特定 LLM 服務商或第三方整合功能，否則資料將僅保留在使用者自己的裝置上。
- **模型無關**：不繫結特定模型，使用者可以根據需求接入各種模型。
- **跨平臺支援**：目前已可在 Mac 上執行，Windows 版本開發中。

💡 **如何運作：從「對話」轉向「交付成品」**

傳統使用 LLM 的流程通常需要人工介入：分析需求 → 生成文本 → 手動查詢檔案 → 調整格式 → 切換軟體傳送。

OpenWorker 試圖將這條鏈路自動化。它會自行拆解任務，並呼叫電腦中的檔案、終端機（Terminal）以及已連線的應用程式，最後直接交付一份可以開啟、修改或分享的成品。

- **情境範例**：你只需說「幫我準備客戶簡報」，它會主動尋找相關資料、整理客戶資訊，最後生成完整的檔案，而非僅僅列出大綱。
- **自動化任務**：它能與大模型配合執行定時任務，例如每天早上自動整理資訊簡報、每週生成工作報告，或持續監控特定 Slack 頻道。

🛠️ **強大的工具整合能力**

OpenWorker 就像是為大模型配上了辦公桌與工具箱，讓大模型負責思考，而 OpenWorker 負責動手操作。

- **預設工具**：專案主頁顯示可連線超過 25 種工具，包含 GitHub、Slack、Jira、Notion、Linear、HubSpot、Outlook、Gmail、Google Calendar 等。
- **擴充性**：若預設工具不足，使用者可以透過 MCP（Model Context Protocol）繼續接入更多工具。
- **模型接入方式**：
  - 透過 API Key 接入雲端模型（如 GPT 5.6 Sol、Claude Fable、Gemini 3.6 等）。
  - 透過 Ollama 執行開放權重模型（如 Kimi、GLM、DeepSeek、Inkling 等）。

🎯 **實務啟示**

對於工程師與自動化流程設計者而言，OpenWorker 的出現標誌著 Agent 的演進方向：從瀏覽器或程式碼編輯器，延伸到了作業系統的「桌面層級」。這意味著未來的 AI 工作流將不再侷限於單一軟體，而是能夠橫跨多個工作工具進行協作。
