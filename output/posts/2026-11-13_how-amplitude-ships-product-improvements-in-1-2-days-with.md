📌 【OpenAI 官方案例】Amplitude 用 AI agent 把產品迭代壓縮到 1-2 天

TL;DR：Amplitude 打造主動式產品 agent「Wave」，讓團隊從發現問題到上線僅需 1-2 天。

產品團隊最熟悉的痛點，往往不是「不知道要做什麼」，而是「知道了,但排期、開發、驗證要拖上好幾週」。OpenAI 官方部落格分享的案例指出，分析公司 Amplitude 用自家打造的 agent，把這段流程大幅壓縮。

🤔 **從「人去找問題」到「agent 主動報告」**

根據 OpenAI 的介紹，Amplitude 建立了一個名為 Wave 的「主動式產品 agent」（proactive product agent），主要建構在 OpenAI 的模型之上。與傳統做法不同的是，Wave 不是被動等待 PM 下指令分析資料，而是主動識別「該建什麼」（what to build）。

🧩 **一條龍：找方向、動手改、看效果**

素材描述 Wave 的工作流程包含三個環節：
- 識別：找出產品中值得改進的機會點。
- 協作開發：協助團隊搭配 coding agent 來實際動手修改並上線。
- 衡量：追蹤這些改動上線後的實際影響。

這等於把「洞察 → 開發 → 驗證」三個傳統上分屬不同角色、不同工具的階段，串接進同一個 agent 驅動的流程裡。

📊 **1-2 天的節奏**

標題直接點出成果：Amplitude 藉此能在 1-2 天內完成產品改進的上線（ship product improvements in 1–2 days）。這個時間尺度,相較於一般產品團隊動輒以週為單位的迭代週期,是本案例最值得工程團隊關注的數字。

🎯 **實務啟示**

對正在評估是否導入 agent 工作流的團隊而言，Wave 的架構提供了一個具體的參考方向：把「資料分析」「程式修改」「效果追蹤」三件事交給同一套 agent 系統串連,而不是分散在不同工具與人力手中銜接。這也呼應了近期產業對「agent 不只是寫 code，還要負責找問題與驗證結果」的討論方向。
