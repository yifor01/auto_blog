📌 Anthropic 推出 Claude Duet：能幫你訂票付款，卻看不到你的密碼

TL;DR：研究預覽版 Claude Duet 可代操作連接的 App，憑證與審批機制皆與模型隔離。

一個能在你離線時幫你讀信、訂東西、付款的 AI agent，聽起來像是資安事件的起點。但 Anthropic 的設計思路反而是反過來做：讓這個 agent 連碰都碰不到你的密碼。

🤔 **一個會在你不在時持續工作的 agent**

Claude Duet 目前處於研究預覽階段，是一個使用雲端電腦代替使用者工作的 agent。它可以使用你已連接到 Claude 的所有 App 與服務，即使關掉應用程式也會持續運作，能讀取收件匣、草擬回覆、代訂東西，並在你不在時執行既定的常規任務。Anthropic 團隊表示他們自己每天都在用 Claude Duet 處理工作。整個設計建立在三個原則上：你和他人在連接 App 中分享的資訊會被謹慎處理（透過一個新的分類器檢查即將送出的訊息）；你始終保有對它行為的控制權；以及它永遠看不到你的密碼、瀏覽器 cookie、登入權杖等憑證。這延續了 Anthropic 在 2025 年發表的「安全且可信任的 agent」框架，以及後續討論「沒有單一防線足夠」「模型內部的防護不能單獨存在」的觀點，同樣的憑證隔離手法也用在他們為企業提供的 Claude Managed Agents 架構上。

🧩 **審批機制：模型看不到答案**

在執行像是傳送敏感訊息、付款、刪除項目這類動作之前，Claude Duet 會先展示這個動作的內容、目的地與所有收件人，等待使用者核准。與此同時，另有一道獨立的自動檢查會同步運作，它建立在 Claude Code 的 auto mode 分類器之上並做了延伸，用來判斷這個動作是否符合使用者原本的意圖；這道檢查跑在模型之外，所以頁面裡藏的惡意指令無法影響檢查結果。有些動作即使使用者核准也不能執行，例如交易證券、在帳戶間轉帳的銀行動作、存取他人帳戶；另外像付款／轉帳、刪除訂單、建立帳號這類步驟，不論核准過多少次,都不受「不要再問我」規則的保護。Anthropic 坦言花了不少時間校準詢問頻率的節奏,因為「核准疲勞」是個真實問題——問太多次,人會不經思考就一路按下去。至於實際付款,Claude Duet 使用類似 Stripe 的 Link 錢包產生的單次虛擬卡,金額與商家都被限定,使用者在 Link App 裡核准,真實卡號不會傳給 Claude Duet 或商家。

💡 **資訊外流前的第二道關卡**

除了動作層級的審批,Anthropic 另外打造了一個與主模型分開運作的安全分類器,專門檢查 Claude Duet 準備送出的每一則訊息是否含有敏感資訊。資訊被分成兩個層級:「絕不分享」涵蓋登入憑證、完整信用卡與銀行帳號、政府身分證號等,Claude Duet 被指示即使使用者要求也不會分享這些;「需經同意才能分享」則涵蓋健康或財務等私人資訊,只有在使用者明確同意後才會分享——而使用者自己的請求本身就算是一種同意,例如「幫我寫封信跟牙醫說我牙痛」通常不需要額外核準。如果訊息被這兩種理由擋下,Claude Duet 可以選擇改寫掉敏感內容,再拿去請使用者核准。Anthropic 也承認,這套分類器仍處於研究預覽階段,偶爾會漏掉真正敏感的內容,也可能誤判無害訊息,所以它是和上述審批機制搭配運作,而非唯一防線。

📊 **你能看到它在做什麼,也能隨時喊停**

使用者可以在任務列表中看到 Claude Duet 做過與正在做的事,每個任務有自己的頁面,也能在任務進行中介入調整方向。它會保留對話記錄與記憶,以便在不同任務間延續上下文,直到使用者刪除或重置記憶為止;刪除帳號會清空它儲存的一切。使用者連接到 Claude 的 App,會同步出現在 Claude Duet 裡,在任一端關閉某個 App 的連接,兩邊都會同步關閉;但中斷連接只會阻止新的存取,它先前從該 App 學到的資訊仍會保留,直到使用者主動重置記憶。Claude Duet 也會使用使用者 Claude 帳號裡原有的記憶。

🧩 **憑證與瀏覽器被徹底隔離在模型之外**

Claude Duet 永遠看不到密碼、瀏覽器 cookie 或連接 App 的登入權杖,也無法把它們存進記憶。當網站要求輸入密碼時,使用者是在 Claude App 裡的表單輸入,這組密碼會用一個只存在於雲端安全瀏覽器機器上的單次金鑰加密,以加密狀態傳給瀏覽器輸入到網站上,模型本身看不到也存不下這組密碼。Anthropic 表示不久後還會支援用 1Password 登入,使用者在 1Password 裡核准請求,憑證會直接送到瀏覽器而不經過模型。這種設計讓釣魚攻擊的風險換了一個樣子:一方面 Claude Duet 本身不持有憑證,無法被釣走密碼,頁面裡藏的指令也套不出一個它根本沒有的秘密;但另一方面,登入表單本身變成了被模仿的目標,因此 Claude Duet 的登入表單只會出現在 App 內、且只在使用者主動要求登入時出現,絕不會以連結、簡訊、email 或其他網站的形式出現——只要看到類似的登入要求出現在別處,就代表不是真的。至於連接 App 時使用的登入權杖,則遵循 Claude Managed Agents 的設計,代表使用者執行動作所需的憑證永遠不會進入 agent 實際工作的那臺機器。

⚠️ **仍在研究預覽階段**

Anthropic 多次強調,這些安全機制目前都還在持續迭代,分類器偶爾會漏判或誤判,因此才需要審批機制與安全分類器彼此搭配,而不是依賴單一防線。

🎯 **實務啟示**

對正在評估或打造類似 agent 系統的工程團隊來說,Claude Duet 的架構給出一個清楚的參考:把「模型」與「憑證平面」徹底拆開,再加上一道跑在模型外部、無法被提示注入影響的意圖檢查分類器,是讓離線運作的 agent 可以被信任的關鍵設計,而不是單靠模型本身學會「不要做壞事」。
