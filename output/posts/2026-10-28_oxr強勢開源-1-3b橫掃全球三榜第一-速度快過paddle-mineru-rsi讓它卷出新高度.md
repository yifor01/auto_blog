📌 1.3B 模型解析文件,速度甩開 PaddleOCR 與 MinerU

TL;DR：OXR 以 1.3B 參數橫掃三大文件解析榜單第一,靠雙階段架構兼顧精度與速度。

文件解析這條賽道一直有個反直覺的現象:模型越大不一定解析越準,反而常常是速度與精度互相拖累。OXR 開源一週就衝上 GitHub 超過 1000 star、X 平臺關注度破百萬,原因就是它用一個只有 1.3B 參數的主模型,同時拿下三項基準測試第一,解析速度還超過參數量更大的對手。

🤔 **從 OCR 到 OXR,要處理的不只是文字**

OXR 全稱是 Optical Everything Recognition,背後團隊是深耕文件智慧領域的 SoMark。它要解決的問題遠不止文字辨識:能解析表格、公式、化學式等 13 類文件元素,還原多欄版面的正確閱讀順序,輸出 Markdown 或 JSON,並保留版面座標。這些能力讓複雜文件轉換成 Agent 或 RAG 流程可以直接繼續使用的結構化資料。例如跨行跨列的表格會輸出為 HTML,保留行列與合併單元格的結構;數學公式輸出為 LaTeX;化學反應式用 mhchem 表示,化學結構式則用 SMILES 表示,把頁面上的圖形變成可繼續處理的文字表達。

🧩 **雙階段架構:輕量版面分析 + 主模型內容識別,排序直接併入識別階段**

OXR 在任務分工上採用一個關鍵設計:由一個輕量版面分析模型先定位內容區域,再交由主模型完成內容識別與閱讀順序判斷。把閱讀順序判斷併入內容識別階段,減少了單獨處理排序的額外開銷,也讓模型能結合內容語義來判斷先後關係,這是 OXR 同時兼顧解析品質與效率的核心架構設計。

版面分析模組被設計成獨立、可插拔的元件。開發者可以直接用內建版面分析模型,也可以換成符合自身業務標準的其他版面分析模型,調整元素類別、區域邊界與內容分組方式,再繼續沿用 OXR 的內容識別與閱讀順序判斷能力。這解決了一個實務上常見的分歧:同一組圖片,資料歸檔可能想整體保留,圖片檢索卻需要逐張提取,兩種需求都合理,但需要的版面處理邏輯不同。

💡 **RSI:用錯樣本和弱樣本持續餵養下一輪訓練**

訓練思路上,OXR 在後訓練階段首次針對文件解析引入「遞迴自我改進」(Recursive Self-Improvement, RSI)範式。流程可以理解為多個 AI 模型協作的「查錯與補課」:OXR 先解析無標籤文件產生待評估結果,外部模型逐樣本分析錯誤原因,獨立聚類模型把問題依原因歸類,再由外部模型圍繞這些問題定向生成訓練資料,用於下一輪 OXR 訓練。這讓訓練資料的補充有明確的問題指向,且整個閉環新增的訓練資料不需要人工標註,突破了人工準備材料造成的效率瓶頸。

📊 **團隊公布的評測結果:三榜第一,速度也領先**

依 SoMark 團隊公布的數據,OXR 在 OmniDocBench、olmOCR-Bench 與 DocParsingBench 分別取得 97.18、87.84 與 87.76 分,均排名第一。速度方面,在同一張 RTX PRO 6000 Blackwell(96GB)顯示卡上,解析從 OmniDocBench 隨機抽取的 100 頁文件,OXR 平均耗時約 101 秒,PaddleOCR-VL-1.6 約需 145 秒,MinerU2.5-Pro 約需 255 秒。

🎯 **對 RAG / Agent 開發者的實務啟示**

目前 OXR 已開放程式碼與模型權重,並提供線上 Demo 與免費 API,方便開發者用真實文件直接驗證效果。對於正在建構 RAG、Agent 或文件工作流的團隊,版面分析可插拔的設計意味著可以先用內建模型快速上手,日後再依業務需求換成客製化的版面分析模型,而不需要重寫整套內容識別邏輯。需留意的是,以上效能與精度數據為團隊自行公布的評測結果,實際導入前仍建議用自己的文件集驗證。
