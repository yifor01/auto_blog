🤔 **什麼是 Agentic Engineering？**

指南開篇即定義核心概念：Agentic Engineering 不只是用 LLM 生成片段，而是將開發任務拆解為可驗證、可迭代、可委派給代理人的工作單元。重點在於「寫 Code 現在很便宜」，瓶頸轉移至如何驗證、整合與維護 AI 產出的程式碼。

README 列出的章節直接映射到開發全生命週期：

其中 Subagents、Red/green TDD、First run the tests 三章特別強調「將驗證責任交給 Agent 自己跑」，而非人工檢查——這正是從「生成」邁向「自主迭代」的關鍵。

💡 **反模式與提示詞庫同等重要**

Anti-patterns 章節點出常見陷阱：過度信任單次生成、忽略版本控制紀錄、讓 Agent 直接改生產環境而無測試保護。Prompts I use 則公開作者實際投入生產的提示詞模板，可直接參考或改寫。

🎯 **實務啟示**

1. **建立「可跑測試」的專案骨架**：Agent 能否自主迭代，取決於 `pytest`/`vitest` 能否一鍵通過。
2. **用 Subagent 分離關注點**：將「重構」、「寫測試」、「更新文件」拆成不同 Subagent，避免單一上下文污染。
3. **把 Git 當作 Agent 的 Undo/Redo**：每次 Agent 操作前自動 commit，失敗即 reset，降低試錯成本。
4. **收集可重用 Prompt**：將成功案例沉澱為 Prompt Library，下次同類任務直接調用。
