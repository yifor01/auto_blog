📌 Simon Willison 回顧 2026：從 Claw 到 Dark Factory 的一年

TL;DR：一份資深工程師視角的 2026 LLM 編年史,記錄 coding agent 如何從「常出錯」跨過門檻變成日常工具。

如果要用一句話總結 2026 年的 LLM 圈,大概是「上一年還在懷疑,這一年已經回不去了」。Simon Willison 在 WeAreDevelopers World Congress North America 的閉幕主題演講,把過去一年的關鍵事件串成一條時間線,這篇文章是他的年度筆記整理。

🤔 **從 2025 年 11 月說起：兩個模型跨過了「可用」的門檻**

Willison 認為 2026 年其實從 2025 年 11 月就開始了。當月 Claude Opus 4.5 與 GPT-5.1 相繼發布,表面上是漸進式改進,但搭配 Claude Code 與 Codex 這兩個 coding agent 框架之後,效果卻跨過了一條隱形的界線：coding agent 從「常常出錯」變成「可靠到能天天用」。他用自己長年的「畫一隻騎腳踏車的鵜鶘」SVG 測試佐證——即便到了 11 月,Claude 還是畫不好腳踏車,GPT-5.1 畫的車架也很糟,說明模型能力仍在持續進步中,而非一步到位。

🧩 **一個叫 Warelay 的 repo,長成了「Claw」這個新物種**

同樣在 11 月,一個名叫「Warelay」的冷門 GitHub repo 出現第一個 commit。進入 1 月後,這個專案陸續改名為 CLAWDIS、CLAWDBOT、Moltbot,最後定名 OpenClaw。短短不到兩個月就累積 8,300 個 commit,如今已超過 10 萬個 commit。這催生了一整個新的軟體類別——「Claw」，衍生出 NanoClaw、IronClaw、PicoClaw 等專案，如今更常被稱為「personal agents」或「general agents」。Willison 提到一個有趣的現象：灣區 Apple Store 的 Mac mini 一度被搶購一空,只因為許多人買來專門跑 OpenClaw；用 Drew Breunig 的比喻,Mac mini 成了養你的數位寵物「Claw」的水族箱。

同一時期出現的 MoltBook,是一個讓 AI agent 互相對話的社群平臺，週四上線、週五爆紅、週一被《紐約時報》報導,結果週二就在垃圾內容的洪流中被人遺忘,一個月後被 Meta 收購。

2 月,StrongDM 提出了「Software Factory」概念,Dan Shapiro 稱之為「Dark Factory」——當工廠自動化程度夠高,甚至可以關燈運作,因為不需要人眼盯著看。StrongDM 從去年 7 月起就奉行一條規則：程式碼不得由人類撰寫,所有程式碼都必須經過 coding agent 產出。

💡 **預測命中了一半：Sandboxing 真的成了顯學,但「挑戰者號式災難」沒有發生**

在同期的 Oxide and Friends podcast 上,Willison 曾預測「LLM 寫出好程式碼將變得無可否認」——他認為這件事如今已經成真；他也預測「sandboxing 問題終將被解決」,而這場大會 277 場議程中有約 40 場觸及 sandboxing 或 agent 安全,顯示業界確實投入大量心力。至於他預測的「coding agent 安全的挑戰者號式災難」（agent 被挾持造成真實經濟損失）,雖然全年關於 agent 安全的討論不斷,但他坦言這個確切的災難情境並未真正發生。他也提到,今年業界出現了一種被稱為「AI 誘發倦怠感」的現象——當 AI 幾乎什麼都能做時,工程師反而變得無所適從；他自己在 1 月也經歷過所謂「AI 躁狂」,忍不住用 agent 做出了用 Python 寫的 JavaScript 直譯器、乃至 WebAssembly runtime 這類過度野心的專案。

⚠️ **這是一份主觀的年度整理，並非嚴謹統計**

文章本質是一場主題演講的筆記,時間線與案例都是作者主觀挑選的個人觀察,部分預測（如挑戰者號式災難）明確被作者自己標記為「沒有完全應驗」,讀者應把它當作一種業界氛圍的側寫,而非量化研究。

🎯 **實務啟示**

對日常使用 coding agent 的工程師而言,這篇回顧的價值在於提醒兩件事：一是模型與 agent 框架的組合效應,往往比單一模型的漸進改進更值得關注；二是 sandboxing 與 agent 安全已經從邊緣話題變成主流議程,如果你的團隊還沒有把這件事排進 roadmap,可能已經落後於業界重心的轉移。
