📌 幫 Agent 選模型的公司，為什麼自己也開始訓練模型？

TL;DR：前華為盤古負責人王雲鶴創業後首發 Agent-Native 模型 NeoHorse，把路由執行的失敗與修復軌跡直接餵進模型訓練。

一直強調「模型不歸一」、靠幫 Agent 挑模型維生的基元律動，這次卻反過來自己訓練了一個模型。這個看似矛盾的動作，答案其實藏在他們過去多模型執行留下的日誌裡。

🤔 分數評不出 Agent 真正的能力

當模型只是回答單一問題時，分數還算是個可靠的比較基準。但一旦模型被放進 Agent 系統去完成一項完整任務，它就得持續讀取環境反饋、處理錯誤、根據實際進展調整路徑，不同環節對能力的要求也不同，單一分數的解釋力因此下降。基元律動團隊由此判斷，模型不歸一會是 AI 產業長期存在的結構：模型越多、分工越細，就越需要一套系統回答「這一步該用哪個模型」「哪個環節可以降級」「什麼時候該升級」之類的問題。他們把這層系統稱為 Routing Harness，旗下開源專案 OpenSquilla 已經接入多款模型，做細粒度路由與模型切換。

🧩 把路由日誌，變成訓練資料

NeoHorse 的核心語料，是把 Routing Harness 產生的 Agent 執行訊號結合公開資料，構建成面向 Agent 後訓練的資料體系。一次任務的完整執行鏈大致是：

輸入任務 → 路由器判斷需要什麼能力 → 選擇某個模型 → 模型推理與工具呼叫 → 環境返回結果 → 模型繼續執行或發生錯誤 → 系統切換模型或調整路徑 → 任務最終完成或失敗

比起一般問答資料只留下「問題」和「答案」兩端，這條軌跡還額外保留了任務需要什麼能力、系統做出了什麼執行決策、環境給出什麼反饋等資訊。比如路由器一開始判斷某任務只需要普通模型，執行中連續失敗後才升級到更強模型才完成，這條軌跡就同時告訴系統：最初能力判斷可能偏低、模型在哪一步出錯、更強模型用了什麼策略、哪條路徑通過了環境驗證。

不過並非所有日誌都值得學。基元律動先對每條軌跡做結構檢查，確認請求、模型回覆、工具呼叫與環境結果能互相對應，接著從六個維度評估執行品質，包括是否完成使用者目標、是否遵守指令、工具使用是否合理、結論有沒有證據支撐、出錯後能否恢復，以及是否在合適時機終止任務——文中特別強調，任務結束不等於使用者目標被滿足，模型說「完成」只代表流程停止，不代表交付物真的達標，因此完成狀態、目標滿足度、環境證據需要分開記錄。

篩選完的資料還搭配兩項訓練方法：一是 Routing-Guided Curriculum（路由引導的課程學習），依路由器估計的任務難度安排學習順序，先學能力需求較低的任務，再逐步加入更複雜的執行軌跡；二是 On-Policy Distillation，讓學生模型先按自己的方式解題，再由教師模型針對學生實際走到的步驟給出指導，而非套用預先準備好的標準錯誤。

📊 4B 模型追上 9B 基礎模型

NeoHorse-1 有 4B 和 9B 兩個版本。根據技術報告，在涵蓋 Harness Agent、工具使用、程式碼和指令遵循等 10 項評測中，NeoHorse-1-4B 經過 Agentic Post-Training 後，綜合表現（宏平均得分從 58.94 提升到 64.87）已經達到同規模 SOTA，在所有可對比基準上超越其基礎模型 Qwen3.5-4B，並在 4B 同規模對比模型中綜合領先。

進一步拆解可以看到，提升主要集中在工作流程相對明確、環境反饋可觀察、成敗可驗證的任務上。文中舉了一個專案排期的例子：基礎模型雖然找到工作目錄裡的檔案，卻沒繼續讀取包含最新依賴約束的郵件，於是按過期資訊生成計劃並存錯位置；後訓練後的模型則會繼續讀取新證據，發現約束變化，重新計算排期並驗證後才存到正確位置。

💡 這是通往 RSI 的第一步，但還不是完整的 RSI

基元律動開始談論 RSI（Recursive Self-Improvement，遞迴自我改進），目前驗證的範圍拆成兩部分：Data-RSI（模型在 Harness 中持續執行任務，產生的結構化記錄篩選後進入訓練資料池，資料量隨系統使用增加）與 Model-RSI（系統依評測結果找出能力短板，調整下一輪訓練資料分佈，更新後的模型再放回 Harness 執行）。文中也坦言，這目前只是一次「執行—評估—選擇—更新」的單輪工程驗證，訊號設計、獎勵設計和訓練流程仍由人類設定，多代模型迭代能否持續獲得增益，還需要更多實驗確認。

⚠️ 還要跨過幾道關

文章列出幾個待觀察的變數：開源生態能否持續轉化成 API 使用與收入、系統能否持續獲得足夠高品質的 Agent 軌跡、模型能力改善能否穩定轉化成經營數據，以及多輪迭代後增益還能持續多久。另外一個繞不開的變數是，DeepSeek、Qwen、MiniMax 等模型廠商也在向 Harness 和 Agent 產品延伸，模型與 Agent 基礎設施垂直整合的趨勢越來越明顯，這可能壓縮基元律動這類「中間層」的生存空間。

🎯 實務啟示

對正在建置 Agent 系統的工程團隊來說，這個案例值得參考的地方在於：多模型執行過程中留下的失敗、切換、修復軌跡，本身就是有訓練價值的資料資產，而不只是拿來 debug 的日誌。如果你的系統本來就有路由或多模型協作機制，或許值得認真思考怎麼把這些執行軌跡結構化保存下來。
