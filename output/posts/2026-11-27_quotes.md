📌 從黎曼猜想到 curl 重寫：AI 圈的三則現場報告

TL;DR：Simon Willison 彙整的近期語錄,揭露 AI 在數學證明、系統重寫與 prompt 設計上的真實進展與落差。

「這次 Claude 不只是跟上,而是飛起來、閃耀。」一位數學家這樣描述他與 Claude 合作逼近黎曼猜想的過程——但同一週,另一位開源維護者卻在說,AI 重寫出來的三十多萬行 Rust 程式碼,一個 bug 都沒修過。

🤔 **背景:同一股力量,三個不同的落地現場**

Simon Willison 的 quotations 頁面持續收錄業界人士對 AI 現況的第一手評論。這次收錄的三段話,分別來自數學研究、開源系統維運,以及 Anthropic 自家的 prompt engineering 文件,正好呈現同一股 AI 能力在不同場域的進展與落差。

🧩 **三個值得放進工程雷達的片段**

第一段來自數學家 Levent Alpöge。他寫道自己「相信」與 Claude 合作發現了黎曼猜想的證明,方法還能延伸到廣義黎曼猜想,甚至有望處理推廣黎曼猜想,兩人也已將論證做了形式化。幾乎同時,Ravi Vakil 提到另一位數學家 Alessandro Masullo 的廣義黎曼猜想證明草稿「全部由人類完成,沒有 AI」,且已由 Brian Conrad 審閱數月。這兩則都只是「聲稱」與「審稿中的草稿」,尚未經過同行徹底驗證,不宜當作已證實的數學結論。

第二段來自 curl 的作者 Daniel Stenberg。他寫道,在 AI agent 把 18.5 萬行 C 程式碼轉換成 34 萬行 Rust 程式碼的這段時間裡,curl 專案本身合併了超過 300 個 commit、修了 200 多個 bug,還修了幾個安全漏洞——而這些修正,一個都沒出現在那些 Rust 重寫版本裡。他的問句是:這些複製品追得上嗎?

第三段來自 Anthropic 針對 Claude Fable 5.2 的 prompt engineering 文件。文件指出,在小型 coding 任務測試中,如果 prompt 沒說清楚程式碼的歸屬,或暗示這是「別人的」程式碼,模型傾向直接在既有結構上疊加,即使這會造成重複;但若明確告知「你是這個程式碼庫的擁有者與長期維護者,設計由你決定」,模型合併重複程式碼的比例從不到 10% 跳到大約 75%。

💡 **深入分析:速度到位了,判斷力還沒**

三則各自指向同一件事：agent 的產出速度與規模已經到位,但「誰在為正確性與脈絡負責」仍是人類的工作。curl 的例子說明規模化重寫容易掩蓋長尾的維運債;ownership prompt 的實驗則說明,同一個模型的行為可以被一句話的角色設定大幅改變,prompt 設計本身就是工程槓桿,而不只是修飾用語。

⚠️ **限制**

黎曼猜想相關的兩則都還停留在「聲稱」與「審稿中」的階段,並非已經確認的數學突破;curl 與 ownership prompt 的數字也只是作者各自引用的觀察,不是對照實驗報告,解讀時應保留這層不確定性。

🎯 **實務啟示**

如果你在用 agent 做大規模程式碼遷移,要像 Stenberg 一樣追蹤「原專案在同一時間做了什麼」,不要只看遷移規模;如果你想讓 agent 在重構時主動整併重複程式碼,試著在 system prompt 裡明確賦予它「擁有者」身份,而不是假設它會自己判斷。
