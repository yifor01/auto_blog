📌 一句話生成架構圖：Archify 衝上 GitHub 熱榜背後的故事

TL;DR：開源 Agent Skill Archify 讓 Claude Code、Cursor 等 coding agent 一鍵生成可互動架構圖，四個月內衝上 GitHub Trending 第一。

手動畫架構圖最痛苦的地方，從來不是畫第一版，而是程式碼一改、圖就過期，然後又得重新拉一次畫布。用 Mermaid 生成雖然方便，但複雜一點箭頭就可能亂飛，最後還是得手動修。開源專案 Archify 把這整件事壓縮成一句話：「分析這個程式碼倉庫，並生成一張高層執行時架構圖。」

🤔 **文字生成圖不是新鮮事，問題出在「畫得快不等於畫得對」**

Mermaid、D2 這類文字生成圖工具早就存在，但它們的工作主要是把已經寫好的文字描述渲染成圖片。Archify 面對的問題更根本：AI 模型可以很快畫出一張架構圖，但不保證這張圖是對的。

🧩 **把繪圖能力嵌進 coding agent 的工作流**

Archify 是一個面向 Claude Code、Codex、Cursor、OpenCode 等 AI agent 的 Agent Skill，不挑底層模型。使用者可以給它一段系統描述，也可以讓它直接分析程式碼倉庫。整個流程大致是：程式碼或文字描述 → Archify 理解 → 生成結構化 JSON IR → 規則驗證 → 渲染成 HTML／SVG → 互動與匯出。目前支援架構圖、工作流圖、時序圖、資料流圖與生命週期圖五類技術圖表，最終輸出一個獨立的 HTML 檔案。

生成的圖不只是拿來看：可以搜尋節點、檢視某個模組的上下游、追蹤兩個節點間的呼叫路徑，也能切換深淺主題，並匯出 PNG、SVG、WebM 及分享卡片。若對結果不滿意，還能直接用自然語言下指令修改，例如「加入 Redis」「把認證模組移到左邊」「突出快取失效後的回退路徑」。

交付前，Archify 會檢查資料結構、節點佈局、標籤與連線是否有衝突；驗證失敗時，它會指出具體問題與允許採用的修復方式，而不是直接交付一張好看但有錯的圖。它還能比較兩張架構快照，以 Before／Delta／After 的方式標出新增、刪除、修改、移動與重新路由的部分，讓架構圖有機會參與程式碼審查、跟著專案一起迭代，而不只是開發結束後才補上的插圖。

📊 **四個月衝上熱榜第一**

截至報導發稿，Archify 已在 X 上獲得多篇十萬讚等級的正向評測，累積 1.9k Fork、3.14 萬 Star，並衝上 GitHub 熱榜第一名。

⚠️ **它不是即時監控系統**

開發者坦言 Archify 並不完美：它不是即時監控系統，也無法自動證明圖與線上實際執行狀態完全一致，結果準確與否仍取決於程式碼資訊、使用者提示與 agent 本身的分析能力。也有網友實測後反映，節點的詳情展示偏小、搭配沒有原生視覺能力的模型（如 deepseek-v4-flash）時體驗不太順暢、消耗的額度也偏高。開發者表示正在更新版本、努力解決這些問題。

Archify 背後的開發者「也無風雨也霧晴」並非名校出身：他讀過專科，以專升本考試同批次第一名的成績考入重慶郵電大學軟體工程專業，求職路上多次在背景調查階段因學歷被刷掉。在時任 Manus 營運長 Cz Chen 的建議下，他選擇走上開源之路，用作品證明自己的能力，最終憑藉開源專案拿到大廠 Offer。Archify 走紅後，他把這段經歷公開分享，也讓這款工具的故事不只是「一個專案四個月內爆紅」，還多了一層關於學歷之外如何證明自己的意義。
